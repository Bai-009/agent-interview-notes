# 高频追问速查

`更新: 2026-08-29`

> 从各题「追问链」里抽出来的**通用模式**——面试官换个题目还会这么问。

---

## 一、四类通用追问（先背这四类）

| 类型 | 追问长什么样 | 应对要点 |
| --- | --- | --- |
| **追问机制** | "为什么这样就能解决？" | 别答现象，答**约束**：它绕开了什么限制 |
| **追问代价** | "这么做的代价是什么？" | 延迟 / 成本 / 复杂度 / 可预测性，至少两条 |
| **追问边界** | "什么情况下**不**该用它？" | 反例场景 + 更优替代 |
| **追问落地** | "你实际怎么做的？效果？" | 必须有**数字**和**取舍**，没有就是没做过 |

## 二、表达层的通用教训

### ⭐⭐ 判断要用判断句说（来自 Q06）

**同样的内容，说法不同，给人的印象完全不同。**

| 不推荐（自我怀疑） | 推荐（判断） |
| --- | --- |
| 「但是我可能理解错了……」 | 「**这道题把两个层面的东西并列了。**」 |
| 「对于模型来说真的会提前想好吗？我会有疑问……」（Q08） | 「**默认循环里模型持有不了跨轮计划，只有贪心的下一步。**」——出题人判定：那个「疑问」就是正确答案 |

和下面「主动说我不知道」那条**不冲突，但要分清**：

- **真的不知道** → 坦白 + 给查证路径 = **加分**
- **已经知道了却包装成不确定** = **主动失分**

判断句的门槛不是"我百分百确定"，是"**我有理由**"。有理由就用判断句，把理由跟上。

### ⭐ 主动说"我不知道 + 我会怎么查"是加分项（来自 Q03）

Q03 里两处坦白（"公式忘了""GLM 怎么实现不清楚，后续该去了解"）被明确判定为**加分而非扣分**。
"我不知道，但我知道该去查什么" 是面试官眼里的高级信号，**明显优于强行编造**。
配套动作：坦白后立刻给出**验证路径**（例：任何"完整有效 1M"的声称，拿 NoLiMa / RULER 量过再信）。

### ⭐ 任何声称，先问「证据是什么基准」（来自 Q03）

"完整有效 1M"这类表述本身不含信息量，含信息量的是它背后那个基准。基准饱和了，声称就等于没说。这一招在评测题（Q19）、选型题（Q14）里同样能用。

### 追问应针对「被一句话带过」的地方（来自 Q05）

Q05 里两句话表述过于顺滑——"数学上不可能非法"和"下一个字段只剩一个"——追进去各挖出一层：一个是状态机预编译的真实实现，一个是对方承认"说得太绝对了"。
**表述过于顺滑，往往意味着有东西被压缩掉了。** 这条对听别人讲解、对面试里被塞结论，都成立。

### ⭐⭐ 讲得最流畅的那一段，最值得拦（来自 Q05、Q09——升级版）

上一条出现第二次了，而且 Q09 给出了它的**成因**，所以升格。

出题人自己的复盘（原话）：*「乱的那一段恰恰是我讲得最流畅的一段——我搜了五篇文章……每一条都有出处，听起来很专业。但那不是教学，那是我在展示我查到了什么。」*

| 现象 | 真实含义 |
| --- | --- |
| 条条有出处、术语密集、衔接顺滑 | 往往是**检索结果的堆叠**，不是机制的推导 |
| 讲的人慢下来、开始认错 | 往往才是真的在解释 |

Q09 里三次拦截**全部成立**（同步/异步、结果凭什么拼接、孙子 Agent 从哪来），三次都发生在对方最流畅的时候。

> **可迁移到面试的两面**：
> ① **听的时候**——「有出处」和「是真的」是两件事，被一串引用推着走时要停下来问「这条撑的是我刚才那个论点吗」。
> ② **自己说的时候**——密集抛术语会被读成「在展示检索量」而不是「懂机制」，这与下面「报不动的引用不如不报」是同一条纪律。

### ⭐⭐ 先把题干拆成待办项，答完逐条对一遍（来自 Q01、Q02、Q08）

**同一习惯已出现三次——它不是失误，是稳定的行为模式，对策必须机械执行。**

| 题 | 题干要求什么 | 实际答了什么 |
| --- | --- | --- |
| Q01 | 两个问号：核心目标是什么 **+ 为什么差十倍** | 只答了第一问 |
| Q02 | 提示明说「**用「分布」一个词把三者统一起来**」 | 答成三段独立描述，统一没交 |
| Q08 | 题干并列三样：**工具、知识和规划** | 只答了工具一根（那一根倒是命中题眼） |

**两次都不是不会——是没响应题目要的那个动作。**

> **内容深度不能替代对题目的响应度。** 一道题深答八分而漏掉半问，通常低于两问都稳稳答到六分。
> 而且 Q01 漏掉的那半问，**恰恰是题库标准答案也没答的地方**——
> **标准答案通常照着第一个问号写，所以第二个问号往往就是超过标准答案的入口。**

**动作**：开口前先默数题干里的要求项（问号、"我要你…"、"结合…说"），答完逐条打勾。

### ⭐⭐ 答题前先扫一遍跨题公共资产表（来自 Q02、Q05、Q09）

**「钥匙已在手上，没认出来」已经出现三次，而且距离一次比一次近：**

| 次 | 需要的东西 | 它当时在哪 | 实际做了什么 |
| --- | --- | --- | --- |
| Q05 | "采样出来的是一个 token" | **自己在 Q04 说过** | 判定为完全没有思路的知识盲区 |
| Q02 | attention sink | **自己的 Q03 记录里写着** | 抓成了"残差连接" |
| Q09 | "主 Agent 看到的是汇报，质量由写它的东西决定" | **自己在同一次作答的上一段说过** | 第三问停在"可以看到状态"，没接上 |

**在 A 题推出的机制，到 B 题需要时调不出来**——前两次隔着一整道题，第三次只隔着一个自然段。

> **所以对策要分两档**：
> - **跨题**：答任何一题前，先扫一眼[跨题公共资产表](题库进度.md#跨题沉淀的公共资产)。**那张表的价值不在于被记录，在于被查阅。**
> - **同题**（Q09 新增）：多问题的题，**答完一问停半秒，问一句「这一问推出的判断，对下一问成立吗」**。Q09 里那半秒就是第三问的全部答案。

### ⭐⭐ 引用的价值 = 你能扛住它带来的追问的程度（来自 Q02）

**报不动的引用，不如不报。**

Q02 查到 CoT 有形式化背书（T 步 CoT ≡ 规模 T 的布尔电路，ICLR 2024）。文献分量很足——**但"布尔电路"这个词一旦出口，下一句大概率就是"那 AC⁰ 是什么意思"。**

> **一条你解释不了的术语，会精确地引来你答不上的那个追问。** 它不是加分项，是自己给自己埋的雷。

**所以引用要分档，默认走最低那档：**

| 档 | 内容 | 何时用 |
| --- | --- | --- |
| **默认** | **只说机制，不带术语** | 永远先用这档。机制说满了就已经够 |
| **加码** | 加一句"这有形式化结论/有论文" | 对方在聊理论时 |
| **追问** | 展开术语本身 | **只有真能讲的时候** |

**推论**：查证的产出**不等于**面试的输入。查到的东西先分档，**扛不住的那档只写进记录，不带进面试**。记录是给自己看的，可以留着慢慢消化；面试里说出口的每一句都要能接住下一问。

### ⭐ 融合异构信号，先问量纲（来自 Q07）

首答把混合检索说成「设权重 α 和 1−α」——BM25 无界、余弦有界，加权和实际由 BM25 主导。工业做法 RRF **不融合分数，融合排名**，把归一化问题整个绕过去。
**可迁移**：任何要把两路信号合成一个数的地方（多路检索、多评委打分、路由决策），先问一句「**这两个数可比吗**」。不可比就别加权，改比名次。

### ⭐ 链路题先找「不可逆步骤」和「天花板指标」（来自 Q07）

pipeline 类题的通用骨架：**错误只往下游传，不往上游修**。所以先指出哪一步不可逆（分块——最上游、没有回头路），哪个指标是天花板（recall@k——它是多少，系统上限就是多少）。
**可迁移**：执行链路（Q17）、长任务（Q18）、评测（Q19）都能用这个骨架开头——比逐环节罗列高一个层级。

### ⭐⭐ 共识以「说出口」为准（来自 Q08）

出题人按「我们推过的东西」出题，被当场顶回：「**在你 context 中的，不一定是我会的**」——出题人接受并自我修正（「以后我只用你说出口的东西」）。

- 对学习：**在讲解里读过 ≠ 会**。掌握的判据是能不能自己说出来（与复习方法「先合上口述」同源）。
- 对复盘：本仓的掌握度只认「用户说出口的推导」，讲解补的内容一律标注来源（🟡 里「哪层是讲解补的」必须写明）。
- 元层：这条纠偏恰是 Q08 题眼的活例——出题人本身是一个被设为教师的 Claude，它把自己 context 里的内容当成了双方共有的记忆，**当场表演了它正在教的机制**：上下文不是记忆，是每轮被重新递过来的文本。

### ⭐ 先检查题目本身是否成立（来自 Q06）

Q06 问"FC 和 RAG 什么时候用哪个"，而这两者根本不在一个层面——**能指出题目是类别错误，比在错误的框架里答得再好都强**。
遇到"A 和 B 二选一"的题，先问：**它们是不是同一类东西？**

## 三、按模块积累

### 模块一 · Prompt 与输入理解

| 追问 | 出处 | 一句话应对 |
| --- | --- | --- |
| 为什么无关内容反而稀释得弱？ | Q03 | key/query 不相似 → exp 后近乎 0 → 不进分母。**半相关内容干扰最强** |
| Lost in the middle 为什么是 U 形？ | Q03 | 算术稀释解释不了，还需**训练中段欠代表** + attention sink + 近因 |
| 怎么量"有效窗口"？ | Q03 | 别用大海捞针（已饱和），用 **NoLiMa / RULER**。RULER 定义：得分 ≥85% 的最大长度 |
| 厂商说自己"完整有效 1M"，信吗？ | Q03 | 先问**拿什么基准撑的**。用 NIAH 撑 = 没撑。GLM-5.2 就是这个情况 |

### 模块一 · Prompt 与推理机制

| 追问 | 出处 | 一句话应对 |
| --- | --- | --- |
| 为什么换个说法效果能差十倍？ | Q01 | 模型**没有"理解意图"这一步**，只是续写最像的下文。两个写法 = **两片语料区** = 两个条件分布，差的是起点不是执行 |
| prompt engineering 是不是已经死了？ | Q01 | **措辞在贬值**（可生成）、**取舍在升值**（架构判断）。它改名叫 context engineering |
| 既然只是续写，为什么它看起来会"规划"？ | Q01 | 训练目标是 next-token，**不代表内部计算只想下一个 token**（Anthropic 归因图：写押韵诗会提前定韵脚） |
| 为什么 system prompt 放最前面就更管用？ | Q02 | **attention sink**（首部 token 吸走不成比例的注意力）+ **后训练过的角色层级**。别答"残差连接" |
| 把恶意指令写进网页，模型会听吗？ | Q02 | **可能会**。所有 token 走同一条通道，优先级只是**学出来的偏好**——提示注入在模型内部不可根治 |
| CoT 为什么能提高准确率？ | Q02 | **两个机制**：① 用 token 买**串行计算深度**（T 步 CoT ≡ 规模 T 的布尔电路）② 中间结果**被序列化、可回读** = 外置工作记忆 |
| 那让模型多输出废话也能变聪明？ | Q02 | 不能。买到的是**步数**，不是**正确的步数**。RLVR 做的就是奖励能通向可验证正确答案的链 |
| CoT 写出来的是它真实的思路吗？ | Q02 | **不保真**。性能提升是实的，**可审计性不是** |
| few-shot 例子越多越好吗？ | Q02 | 不是。对强推理模型**可能降分**（锚死在模仿模式）；且例子**永久占窗口** |

### 模块二 · 模型输出控制（幻觉 / 结构化输出）

| 追问 | 出处 | 一句话应对 |
| --- | --- | --- |
| RAG 能根治幻觉吗？ | Q04 | 不能，**只治第 1 层**（缺信息）。资料错了它照样自信地错 |
| 怎么"看见"模型的不确定？ | Q04 | logprobs + 语义熵（同题跑五次，发散=分布平坦） |
| 为什么 prompt 写"不知道就说不知道"没用？ | Q04 | 在**对抗 RLHF 训练出来的偏好**，prompt 压不过梯度 |
| 幻觉能彻底消除吗？ | Q04 | 不能，结构性产物。目标应从"不出错"转向"**错误可检测**" |
| 幻觉基准做得再好行不行？ | Q04 | 不行。一个幻觉评测敌不过几百个奖励猜测的准确率评测，**得重做主流指标** |
| 约束解码是每步检验几万个 token 吗？ | Q05 | 不是。**开跑前把 schema 编译成状态机**，运行时只查表 |
| 上了 schema 模型是不是被完全锁定？ | Q05 | 不。**结构被强制，内容仍自由**——约束落在语法接缝，不落在自由内容 |
| 约束解码的代价是什么？ | Q05 | **不是慢，是分布被扭曲**：token 边界与语法边界错位，模型被迫走训练时少见的拼法 |
| schema 加个 confidence 能反映把握吗？ | Q05 | **不能**。模型看不见自己的 logits，那个数是模仿，不是测量。要真数自己从 logprobs 算 |
| logprobs 就可靠了吗？ | Q05 | 测的是**措辞**的确定性，不是**事实**的确定性。答案对但低、答案错但高，都存在 |
| 上 schema 会不会伤模型能力？ | Q05 | **有方向性**：推理任务掉 10–15%，**分类/选择任务反而受益**。问题不是"要不要上"，是"这任务要不要模型自己想" |

### 模块二 · 模型输出控制（检索架构）

| 追问 | 出处 | 一句话应对 |
| --- | --- | --- |
| `search_docs()` 算 FC 还是 RAG？ | Q06 | **都算也都不算**——用 FC 这个机制实现 RAG 这个模式。问题本身是类别错误 |
| Claude Code 为什么不用向量检索？ | Q06 | 试过并**拆掉了**。安全/隐私/**索引陈旧**/可靠性——**三条与召回率无关** |
| 那 RAG 是不是过时了？ | Q06 | 不是。**经典 RAG 因可预测性仍是强默认**，agentic 只在需重试/拆解/交叉验证时更优 |
| agentic 检索的代价？ | Q06 | 延迟与 token 成本**不可预测**；简单查询是纯粹的开销浪费；要防止原地循环 |
| 为什么必须混合检索？ | Q07 | 嵌入 = **有损压缩**：训练目标保主题、销稀有符号；BM25 的 IDF 恰好反向。**稀有度轴上强弱完全相反**，而区分度最高的恰是稀有词 |
| 两路的分数怎么合？ | Q07 | **不能加权求和**——BM25 无界、余弦有界，量纲不可比。用 **RRF 按排名融合**（k=60，SIGIR 2009） |
| 向量检索还有什么盲区？ | Q07 | **否定**——且 BM25 同样看不见「不」，多数检索模型在否定对比对上**不如随机**（NevIR）。止损点在 rerank 层 |
| 为什么 rerank 必须存在？ | Q07 | cross-encoder **必须见到 query 才能算 → 不可预计算 → 只能处理短名单**。分层是被逼的，不是设计选择 |
| chunk 大小怎么定？ | Q07 | 张力：小 = 方向纯，大 = 上下文全，两头都塌。**parent-child 解耦**（小块检索、父块生成）；真原则是**切在语义接缝上** |
| 检索系统优化什么指标？ | Q07 | 分层看：召回层 **recall@k（天花板）**、重排层 precision@5。**分块唯一不可逆**——病常在最上游，别只在下游调 top-k |

### 模块三 · Agent 系统设计

| 追问 | 出处 | 一句话应对 |
| --- | --- | --- |
| Agent 怎么「自主」运行？ | Q08 | 自主性**住在循环里不在模型里**：模型只出贪心的下一步，harness 把结果拼回去、决定停不停 |
| tool_use 时模型在执行工具吗？ | Q08 | 不是。**模型只有请求权，执行权在外部代码**——tool_use 是请求，真正跑的是 harness |
| end_turn 就是任务完成吗？ | Q08 | 不是，那只是「这段话说完了」。**完成判定权在验证器**——不过验证就把证据拼回去再调一轮 |
| Agent 的记忆存在哪？ | Q08 | 哪都没存。**模型每轮失忆**，「记忆」是 harness 每轮重拼进输入的文本（tool_result / 笔记 / 检索） |
| 模型会先做个计划再执行吗？ | Q08 | 默认不会也不能——**没有机制持有跨轮计划**。plan mode = 计划文本被固定后每轮重读；要防偏离就升级成**被跟踪的状态**（todo/文件） |
| 那单轮内它也不前瞻吗？ | Q08 | 单次生成**内部**有前瞻证据（Anthropic 归因图）；零携带说的是**跨请求**——前瞻住在激活里，激活不跨请求 |
| 子 Agent 该不该共享主 Agent 的上下文？ | Q09 | 不该，理由是物理的：**主链只增不减**，试错的 token 每轮重付。子 Agent 买的是「**试错发生在别人的链上**」，不是并行速度 |
| 子 Agent 翻过的原文去哪了？ | Q09 | 没了。回报是**摘要**——**有损是设计目的**（防中间产物淹没结论），不是缺陷。补救只有一条：**回报留可抽查的指针**（路径行号） |
| 主 Agent 的上下文为什么「只增不减」？ | Q09 | 不是没人想清理，是**删不起**：前缀缓存改动任一层级 → 该层级及其之后全部失效 → 就地删中间等于那一点之后整段重算。**清理比留着更贵** |
| 子 Agent 崩了主 Agent 怎么知道？ | Q09 | 它不「知道」，它**只读到 harness 代笔的那段文字**。崩了有事件；**卡住没有事件**——超时的作用是**造事件**，不是保护 |
| 那查一下子 Agent 的状态不就行了？ | Q09 | 状态查得到（`running`/`shutdown`），但**状态也是一份汇报，不是事实**：公开缺陷里有报 shutdown 却没执行任务、报 running 却毫无输出、已结束仍占配额、连关闭都挂住 |
| 设个超时兜底总行吧？ | Q09 | **超时若由那个卡住的东西自己执行，它就不是超时**。有记录：设 5 分钟实际阻塞约 7.5 小时。凡是要在别人失灵时生效的机制（超时、取消），**都不能住在别人里面** |
| 那「跑偏了」呢？ | Q09 | 超时救不了：不崩不卡、正常返回。**跑满上限返回「未找到」和跑 5 轮返回「未找到」长得一样**。只能靠验证器 |
| 设了轮数上限不就行了？ | Q09 | **封顶 ≠ 止损**。上限保证会停，不保证停之前有意义；真实浪费是「在上限之内做完了全部无用功」 |
| 用户按 Esc，5 个子 Agent 怎么停？ | Q09 | 取消要走**从外向内的独立通道**（代码/进程层）——**外部世界变了，agent 自己永远不会知道**。且取消要留痕，否则主 Agent 以为它还在跑 |
| 多个子 Agent 的结果怎么合并？ | Q09 | 老实说：**没有通用机制**，合并逻辑由编排代码作者手写。这正是「结构化回报」比自然语言回报重要的原因 |
| 主 Agent 会等第一个完工的吗？ | Q09 | 两种都真实存在，**判据是主 Agent 等待期间有没有别的事可做**：Anthropic 研究系统等待期间无事可做（报告要等素材齐）故同步，Claude Code 等待期间还在跟人对话故异步默认。**别答「主流是哪个」——一个反例就被打掉。** 异步的代价是三件事：半张图上的思考永久留在链上 / 每次唤醒是全额调用 / 失败在你已往前走两步之后才到 |
