# 高频追问速查

`更新: 2026-08-28`

> 从各题「追问链」里抽出来的**通用模式**——面试官换个题目还会这么问。

## 通用追问模板（先背这四把刀）

| 刀法 | 追问长什么样 | 应对要点 |
| --- | --- | --- |
| **挖机制** | "为什么这样就能解决？" | 别答现象，答**约束**：它绕开了什么限制 |
| **问代价** | "这么做的代价是什么？" | 延迟 / 成本 / 复杂度 / 可预测性，至少两条 |
| **划边界** | "什么情况下**不**该用它？" | 反例场景 + 更优替代 |
| **要落地** | "你实际怎么做的？效果？" | 必须有**数字**和**取舍**，没有就是没做过 |

## ⭐ 已验证的加分动作

**主动说"我不知道 + 我会怎么查"。**
Q03 里两处坦白（"公式忘了""GLM 怎么实现不清楚，后续该去了解"）被明确判定为**加分而非扣分**。
"我不知道，但我知道该去查什么" 是面试官眼里的高级信号，**比硬编强十倍**。
配套：坦白后立刻给出**验证路径**（例：任何"完整有效 1M"的声称，拿 NoLiMa/RULER 量过再信）。

**⭐ 另一条：任何声称，先问「证据是什么基准」。**
"完整有效 1M"这类表述本身不含信息量，含信息量的是它背后那个基准。基准饱和了，声称就等于没说。这一招在评测题（Q19）、选型题（Q14）里同样能用。

**追问要打在「这里被一句话带过了」的地方。**
Q05 里两句话太顺滑——"数学上不可能非法"和"下一个字段只剩一个"——追进去各挖出一层：一个是状态机预编译的真实实现，一个是对方承认"说得太绝对了"。
**太顺滑就是有东西被压缩掉了。** 这条对听别人讲解、对面试里被塞结论，都成立。

## 按模块积累

### 二、模型输出控制

| 追问 | 出处 | 一句话应对 |
| --- | --- | --- |
| RAG 能根治幻觉吗？ | Q04 | 不能，**只治第 1 层**（缺信息）。资料错了它照样自信地错 |
| 怎么"看见"模型的不确定？ | Q04 | logprobs + 自洽性采样（同题跑五次，发散=分布平坦） |
| 为什么 prompt 写"不知道就说不知道"没用？ | Q04 | 在**对抗 RLHF 训练出来的偏好**，prompt 压不过梯度 |
| 幻觉能彻底消除吗？ | Q04 | 不能，结构性产物。目标应从"不出错"转向"**错误可检测**" |
| 约束解码是每步检验几万个 token 吗？ | Q05 | 不是。**开跑前把 schema 编译成状态机**，运行时只查表 |
| 上了 schema 模型是不是被完全钉死？ | Q05 | 不。**结构被强制，内容仍自由**——约束落在语法接缝，不落在自由内容 |
| 约束解码的代价是什么？ | Q05 | **不是慢，是分布被扭曲**：token 边界与语法边界错位，模型被迫走训练时少见的拼法 |
| schema 加个 confidence 能反映把握吗？ | Q05 | **不能**。模型看不见自己的 logits，那个数是表演。要真数自己从 logprobs 算 |
| logprobs 就可靠了吗？ | Q05 | 测的是**措辞**的确定性，不是**事实**的确定性。答案对但低、答案错但高，都存在 |
| 上 schema 会不会伤模型能力？ | Q05 | **有方向性**：推理任务掉 10–15%，**分类/选择任务反而受益**。问题不是"要不要上"，是"这任务要不要模型自己想" |
| 幻觉基准做得再好行不行？ | Q04 | 不行。一个幻觉评测敌不过几百个奖励猜测的准确率评测，**得重做主流指标** |

| 追问 | 出处 | 一句话应对 |
