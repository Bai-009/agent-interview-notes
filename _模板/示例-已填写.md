## 4. 完整答案（面试可直接复述）

### 4.1 一句话定义

ReAct 是把**推理（Reasoning）**和**行动（Acting）**交错进行的循环：每一步只决策一个动作，拿到真实 Observation 后再决定下一步。

### 4.2 分层展开

**① 一次性计划的隐含前提是「环境完全可观测」**
让模型开跑前就输出完整计划，等于假设它此刻已经掌握了全部决策依据。但真实任务里，第 3 步该干什么，取决于第 2 步查出来的结果——这个结果在规划时**尚不存在**。前提不成立，计划就是在猜。

**② 误差沿计划链累积**
一次性计划里，第 1 步的错误判断会被后续所有步骤继承，而且**没有纠错点**。N 步计划的成功率大致是逐步正确率的连乘，链越长塌得越快。

**③ ReAct 怎么修：把每一步的生成条件化在真实观测上**
每次只生成一个动作 → 执行 → 把真实返回值写回上下文 → 下一次推理是在「已包含真实事实」的上下文上做的。幻觉减少不是因为「让它想一想」，而是因为**它不再需要凭空想象那个事实了**——事实已经被工具取回来放在上下文里。这就是 grounding。同时每一轮都是一个天然的纠错点。

**④ 代价与边界**
- 延迟和 token 成本随步数线性增长（每轮都要重发上下文）
- 容易**原地循环**：反复调同一个工具 → 必须加步数上限 + 重复动作检测
- 上下文随观测膨胀 → 需要观测截断/摘要
- 任务如果本来就**完全可观测**（步骤固定、无分支，比如「读表 → 转格式 → 写库」），一次性计划甚至写死的工作流更快更稳——**这时候用 ReAct 是过度设计**

### 4.3 加分项（说出来能拉开差距）

- 指出这是一条**光谱**，不是二选一：
  `固定工作流` → `Plan-and-Execute（先规划，失败再重规划）` → `ReWOO（推理与观测解耦，省 token）` → `ReAct（全交错）` → `Reflexion（加自我反思）`
  越往右越灵活、越贵、越难预测。**选型依据是任务的可观测性和分支度，不是「哪个先进」。**
- 一句收尾：「所以我在做 X 项目时，把确定性的前置流程写成固定 pipeline，只在需要根据检索结果决策的那一段用 ReAct，把平均步数从 8 压到 3。」（← 换成你自己的真实数字）

## 5. 第一性原理（往下再挖一层）

- **本质约束**：LLM 是在自己的输出上自回归的，它无法凭空获得外部世界的新信息。要让它的决策依赖外部事实，就必须给事实**开一个进入上下文的口子**——工具调用是这个口子，交错循环是让这个口子在每一步都可用。
- **不这么做会怎样**：模型只能靠参数里的先验去「编」那个它没见过的事实，也就是幻觉。
- **更朴素的替代**：固定工作流。它没被淘汰，反而在生产里占大多数——只要任务分支可枚举，它就更优。ReAct 是为**分支不可枚举**的任务准备的。
