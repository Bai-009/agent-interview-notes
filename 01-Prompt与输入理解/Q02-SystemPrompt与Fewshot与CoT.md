# Q02 System Prompt / Few-shot / CoT 在 Prompt 设计中各起什么作用？

`模块: 一 Prompt与输入理解` `难度: ★★★★☆` `掌握度: 🟡待巩固（CoT 段 🟢）` `首答: 2026-08-28` `复习: 0 次` `上次复习: —` `基线核查: 2026-08-28`

> 判定：**不只过线——CoT 那一段把题库打穿了**，给出的是第一性解释而不是功能描述。
> 但有两处欠账：一处机制说错（「残差连接」应为 **attention sink**），以及**出题人点名要的那个"统一"没交**。

---

## ⚡ 30 秒速览（复习时只看这一块）

- **一句话回答**：三者是对**同一个条件分布**动的三种手术——**System prompt 定分布的底色**（全程条件化），**few-shot 钉分布的形状**（用样本示范代替规则描述），**CoT 把一次尖不起来的采样，拆成一串尖得起来的采样**。
- **必须覆盖的关键词**：`三种手术，同一个分布` `attention sink（不是残差连接）` `角色层级是学出来的偏好，不是架构强制` `提示注入结构上不可根治` `token 换串行计算深度` `中间结果被序列化 = 外置工作记忆` `状态外置的最小版本` `RLVR` `CoT 不保真` `few-shot 对强推理模型可能降分`
- **上次的失分点**：
  1. **「残差连接」用错了。** 残差管的是深度方向上信息不丢，跟"前面的 token 更重要"无关。想抓的那个现象叫 **attention sink**
  2. **点名要的统一没交。** 出题人明说了"用『分布』这一个词把三者统一起来"，答成了三段各自独立的机制描述——**每段都好，但没做那个被要求的动作**
  3. **CoT 只答了一半。** "token 换 layer"完全正确，但漏了更关键的另一半：**写下来的中间结果会变成后续 token 的输入**
- **答题骨架**：① **先给统一框架**（三种手术）→ ② 逐个展开机制 → ③ 每个各挂一条 2026 注脚 → ④ 收在"把一次平坦采样拆成一串尖锐采样"
- ⚠️ **CoT 那条定理默认不报术语**：先说"一次前向的串行计算有硬上限"，`布尔电路 / AC⁰` 留到对方追问且你扛得住时再亮（分档说法见 7.5）

## 1. 题目原文

> System Prompt / Few-shot / CoT 在 Prompt 设计中各起什么作用？

**出题人的提示**：

> 题库的答案是"三个策略解决三个问题"——你可以背出类似的，但**我要你试着更进一步：用"分布"这一个词，把三者统一起来说。三个东西各自在对分布做什么不同的动作？**

**考察意图**：这题是 [[Q01-Prompt核心目标]] 的正面版。题库答案是三句功能描述——**全对，全浅**。真正的分水岭是：**能不能把三个手段收进同一个框架里**。能分别讲清三件事的人很多，能说出"它们在做同一件事的三种变体"的人很少。

## 2. 我的原始回答（不修饰，保留原样）

> system prompt就像该任务的背景音乐，在残差链接的关系和专门后训练的基础下，最前面的提示词会被模型认为是更重要的系统指令。遵循的效果更好，而且由于attention的机制，后续的所有token都会看到前面的系统提示词的内容，也就是始终影响着后续的token的预测和生成。
> few-shot其实就是举例子，模型看不到的对模型而言就是没有，你给到一些例子，本身就是在让模型学习，从而改变了输出的分布，让他更该知道当下的这个问题该如何处理。
> COT，现在的模型都是thinking模型，thinking就可以看作是工业版本的COT，举个例子就很好的说明COT，算9999*9999假如这里面是5个token，假设模型是100层layer层，那么这五个token就走过来500层layer层。模型并不能真实的去额外的思考里面的关系，从而自信的给出一个差不多的答案。如果我给的提示词是先算10000*10000，再减去20000再减去1，用了大概20个token，走过了2000层layer层，并且还降低了单词回答问题的难度，就好像一个是在口算答案，一个是有一张草稿纸把过程写了下来。因为模型的layer层是固定的，所以COT的本质就是在用额外的token换layer层，换模型的聪明。

## 3. 差距诊断

### 3.1 与题库标准答案对照

| | 题库版 | 我的答案 | 判定 |
| --- | --- | --- | --- |
| System Prompt | "解决始终按某角色回答，全程生效" | 给了**两条机制**：位置带来的权重加成 + **专门后训练过的角色层级**；并指出因果注意力让后续每个 token 都看得到它 | ✅ **高于题库**（题库只说效果，没说为什么） |
| Few-shot | "解决格式对齐，给例子比写规则管用" | "模型看不到的对模型而言就是没有"，给例子即改变输出分布 | 🟡 与题库同水准 |
| CoT | "解决复杂推理易错，把过程写出来能纠偏" | **token 换 layer**：模型深度固定，多生成 token = 多走串行计算步数 | ✅✅ **打穿题库**——这是第一性解释，不是功能描述 |

**题库那三句是功能描述：全对，全浅。** 我的答案在 System Prompt 和 CoT 两处明显更深。

### 3.2 四维诊断

| 维度 | 表现 | 说明 |
| --- | --- | --- |
| 概念准确性 | 🟡 | **一处错位**：「残差连接」承担不了"前面的 token 更重要"这个论断 |
| 深度 | 🟢🟢 | CoT 段是全仓目前最好的自主推导之一——**从"深度固定"这个结构事实推出"用 token 买计算"** |
| 结构 | ❌ | **三段并列，没有统一** ——而统一正是出题人点名要的动作 |
| 工程落地感 | 🟡 | 9999×9999 那个例子非常好；但 few-shot 与 system prompt 两段没有对应的落地细节 |

**最致命的一条**：**出题人点名要的那个动作没做。**

提示里写得很清楚——"**用『分布』这一个词，把三者统一起来说**"。答案给的是三段各自独立的机制描述。三段质量都不低，但**题目要的是一个动作（统一），而这个动作没有发生**。

> 📌 **这条和 [[Q01-Prompt核心目标]] 的失分是同一类**：Q01 是题干有两个问号只答了一个，这题是提示里有一个明确指令没有执行。
> **合起来就是一条**：**先把题干要求拆成待办项，答完逐条对一遍。** 内容深度不能替代对题目的响应度。

**次致命**：「残差连接」→ 应为 **attention sink**。

## 4. 完整答案（面试可直接复述）

### 4.1 先给统一框架（这是题眼，必须放最前面）

**三者是对同一个条件分布动的三种手术：**

| | 对分布做什么 | 一句话 |
| --- | --- | --- |
| **System Prompt** | 定分布的**底色** | 全程条件化——每一个后续 token 都在它的条件之下采样 |
| **Few-shot** | 钉分布的**形状** | 用样本示范代替规则描述 |
| **CoT** | 改分布的**采样次数** | 把**一次尖不起来的采样，拆成一串尖得起来的采样** |

> 前两个改的是**这一次采样的分布长什么样**，第三个改的是**采样几次、每次难度多大**。

### 4.2 System Prompt：定底色

**两条机制叠加，缺一条都不完整：**

**① 位置带来的权重加成 —— attention sink**

注意力会**不成比例地锚定在序列最前面的几个 token 上**。这不是设计出来的，是训练出来的自然产物。所以放在最前面的内容，位置本身就自带加成。

**② 角色层级 —— 专门后训练过**

模型被专门训练过「system 说的比 user 说的更该听」。

**③ 因果注意力 —— 全程可见**

因为是因果注意力，**后续每一个 token 都能看到 system prompt**。所以它不是"开头交代一句"，是**对整段生成的持续条件化**。

**生产级推论（这一条最值钱）**：

> **system > user > 工具返回，这个优先级不是架构强制的，是学出来的偏好。**

架构层面，**所有 token 走的是同一条通道、同一套注意力**。没有任何机制把"指令"和"数据"物理隔开。

> **这就是提示注入在结构上无法根治的原因**：指令和数据物理上是同一种东西，"谁该听谁的"只是**一个被训练加强过的倾向**——而倾向可以被足够刁钻的输入压过去。
>
> 所以工具返回值、网页内容、文件正文进上下文时，**它们和 system prompt 在物理上是平级的**。防御只能靠训练偏好 + 外层工程（隔离、标注、最小权限），**不可能靠"我在 system 里写了不要听它的"**。

### 4.3 Few-shot：钉形状

**为什么给例子比写规则管用**：规则是对分布的**描述**，样本是分布的**实例**。模型接的是"最像的下文"，给它实例比给它描述更直接。

**2026 年的反直觉更新（必须知道，否则会答成 2023 年的水准）**：

> **对强推理模型，few-shot 有时反而降分。** 例子会把模型**锚死在模仿模式**上，抑制它自己的推理。

**所以 2026 年的实务是**：

| 场景 | 用什么 |
| --- | --- |
| 格式约束 | **用 schema**（约束解码，见 [[Q05-StructuredOutput]]），别用例子 |
| 推理任务 | **倾向 zero-shot**，直接把问题和输出要求说清楚 |
| 格式怪异且说不清 | **这才是 few-shot 剩下的主场** |

**还有一条隐性成本**：例子**永久占窗口**。每一轮都要重发，而且是最容易被忘记清理的那部分——直接接上 [[Q03-Token与上下文窗口与上下文腐化]] 的零和竞价。

### 4.4 CoT：把一次平坦采样拆成一串尖锐采样

**机制一：token 换串行计算深度**

模型每生成一个 token，只走**一次固定深度的前向传播**。难题硬要一步出答案，等于**逼一个 100 层的电路瞬间完成需要 2000 层的计算**——它做不到，于是给一个"差不多"的答案，而且语气照样笃定。

> **多生成 token = 购买串行计算步数。**

拿 9999×9999 举例：一步出答案，5 个 token 只买到 500 层；拆成「先算 10000×10000，再减 20000，再减 1」，20 个 token 买到 2000 层，**而且每一步单独看都变简单了**。

> 一个是口算，一个是有草稿纸。

**机制二：中间结果被序列化，可以被回读**（这条比换深度更关键）

草稿纸的价值不只是"多算了几步"。**没有 CoT 时，所有中间量只能挤在残差流那点宽度里暗算；写出来之后，`10000×10000 = 100000000` 这个中间结果被序列化进了上下文，后面每一步都能回头读它。**

> **草稿可以被重新读取——它是外置的工作记忆。**

> 🔗 **这就是"状态外置"的最小版本。**
> **Agent 把任务状态写进文件，和模型把中间结果写进上下文，是同一个动作在两个尺度上。** 认出这一点，这题就从"Prompt 技巧题"变成了"Agent 架构题"。→ [[Q08-Agent如何自主运行]]、[[Q17-执行链路与连续任务正确性]]、[[Q18-长任务不偏离目标]]

**注脚一：thinking 模型 = 被 RLVR 训练过的 CoT**

- **原生 CoT** 是"提示出来的习惯"——你写「让我们一步步想」，它照做
- **thinking** 是"被**可验证奖励**强化过的能力"——链条质量完全不同

而且它现在是**可调的成本旋钮**（思考深度档位）。**这一句把 CoT 从技巧升级成了资源分配问题**：什么时候该加思考预算、什么时候是纯烧钱，本身就是一道生产级判断题。

**注脚二：一条诚实的边界 —— 写出来的链不保真**

> **模型可能先"算"出答案，再补一条看起来合理的推导。**

所以：**草稿纸提升性能是实的；但把草稿当成"它真实的思路"去审计，不保真。**

面试里主动说这一句，比"CoT 让模型思考更透明"稳得多——后者会被追问一句就穿。

### 4.5 加分项

- **开口就给统一框架**，三段展开放后面。题目问"各起什么作用"，多数人会给三段并列——**先收后放，立刻拉开差距**。
- **每一段各挂一条 2026 注脚**（system → 提示注入不可根治；few-shot → 对推理模型可能降分；CoT → RLVR + 不保真）。三条注脚都是题库没有的。
- **把 CoT 接到状态外置上**，说明你看到的是同一个动作在两个尺度上，而不是三个孤立技巧。

## 5. 第一性原理（往下再挖一层）

- **本质约束**：可动的只有前缀。所以能做的动作只有三类——**改条件**（system prompt）、**给实例**（few-shot）、**加步数**（CoT）。三者穷尽了"不改权重的前提下能对分布做的事"。
- **为什么 CoT 是三者中最强的**：前两个只能**移动**这一次采样的分布，**移不动它的上限**——如果任务本身需要 2000 层串行计算，把分布调得再准，一次前向也算不出来。CoT 动的是**计算量**这个更底层的量。
- **为什么"角色层级"必然脆弱**：因为它是**统计偏好**而非**类型约束**。凡是靠训练加强的倾向，都可以被分布外的输入压过去。**要真正的隔离，只能在模型外面建**（见 [[Q20-工具调用安全]] 的 Default FAIL）。

## 7.5 查证记录（2026-08-28）

### ✅ 核实通过（四处硬引用全部有一手来源）

| 说法 | 一手来源 | 核实结果 |
| --- | --- | --- |
| **attention sink** | Xiao et al.《Efficient Streaming Language Models with Attention Sinks》，**arXiv:2309.17453**，**ICLR 2024** | ✅ 提出者。观察到注意力在最初几个 token 上出现异常高的权重，命名为 attention sink；StreamingLLM 的做法就是**保留最初几个 token + 最近窗口** |
| **attention sink 的成因** | 《When Attention Sink Emerges in Language Models: An Empirical View》，**arXiv:2410.10781**，**ICLR 2025** | ✅ **首 token 起的是"偏置"作用**——它的 key 与其他 token 的 query 夹角普遍很小；且 sink **在充分数据上优化后自然出现**，是训练的产物。另有一个反直觉细节：首 token 的**隐状态 ℓ2 范数显著更大，但 K/V 的 ℓ2 范数显著更小** |
| **CoT = 用 token 买串行计算深度** | Li, Liu, Zhou, Ma《Chain of Thought Empowers Transformers to Solve Inherently Serial Problems》，**arXiv:2402.12875**，**ICLR 2024** | ✅ **这条直觉是有定理的**，见下方专条 |
| **CoT 不保真** | Anthropic Alignment Science《Reasoning Models Don't Always Say What They Think》，**arXiv:2505.05410**（2025-05） | ✅ 方法是在 prompt 里埋"提示"，对比有无提示两组回答：模型**用了那个提示却常常不在 CoT 里说出来**。结论直指 CoT 监控在安全场景下的可靠性上限 |
| **few-shot 对强推理模型降分** | DeepSeek-R1（Nature 2025, s41586-025-09422-z）及官方使用建议 | ✅ 官方明确：R1 对 prompt 敏感，**few-shot 会稳定地拉低表现**，推荐 **zero-shot** 直接描述问题与输出格式 |

### ➕ 本次新增：那条直觉，是一个定理

> **《Chain of Thought Empowers Transformers to Solve Inherently Serial Problems》** —— Zhiyuan Li、Hong Liu、Denny Zhou、Tengyu Ma，**arXiv:2402.12875**，ICLR 2024。

**它证明的正是"token 换 layer"：**

| | 结论 |
| --- | --- |
| **没有 CoT** | 常数深度、常数位精度的 transformer，表达力上界被卡在 **AC⁰**（并且 AC⁰ ⊊ TC⁰）——**天生解不了本质串行的问题** |
| **有 T 步 CoT** | 同样是常数深度、O(log n) 嵌入维度的 transformer，**可以解任何能被规模为 T 的布尔电路解决的问题** |
| **实验佐证** | 在置换群复合、迭代平方、电路值问题这些**难以并行**的任务上，CoT 带来的提升最显著，且**层数越浅的模型受益越大** |

> **这是本轮查证里分量最重的一条。** 「模型层数是固定的，所以 CoT 的本质是用额外的 token 换 layer」——这个自己推出来的说法，**不是一个好比喻，是一个可以报出论文的定理**。

#### 「布尔电路」「AC⁰」是什么——先看懂，再决定说不说

**布尔电路**：把一次计算画成一张接线图。输入是一串 0/1，从左边进来，穿过一堆 **AND / OR / NOT** 门，右边出结果。描述一张电路只要两个数：

| | 是什么 | 对应到模型 |
| --- | --- | --- |
| **规模**（size） | 一共用了多少个门 | **总计算量** |
| **深度**（depth） | 从输入到输出，最长要**串行**穿过几层门 | **必须一步接一步做的步数** |

**关键在深度**：如果第 2 步要用第 1 步的结果，这两步就没法同时做。**深度量的就是"没法并行的那部分"。**

> **一个固定层数的 transformer，就是一张固定深度的电路。** 一次前向 = 信号穿过 100 层，走完就得出答案。所以它一次能做的**串行步数有硬上限**——这正是你自己说的"layer 层是固定的"。

**AC⁰** 就是"常数深度电路能解的问题"这一类。它有个著名的短板：**AC⁰ 算不出奇偶性**——给一串 0/1，判断里面 1 的个数是奇数还是偶数，常数深度的电路**证明了做不到**。任务简单到荒谬，但它本质上要求你一位一位地累加，**而累加就是串行的**。

**TC⁰** 是加了"多数门"之后更强的一类，AC⁰ ⊊ TC⁰。

所以那条定理说的是：**固定层数的 transformer 被卡在 AC⁰ 里，有些极简单但必须串行的事它一次前向就是做不了；每多生成一个 token，等于给这张电路续上一段新的深度。**

#### 怎么把这条说出口（分档，别一上来就报术语）

| 档 | 说法 | 什么时候用 |
| --- | --- | --- |
| **默认档** | 「模型一次前向只有固定的层数，串行计算量有硬上限。**有些很简单但必须一步接一步做的问题，它一次是算不出来的**。多生成一个 token，就等于给它续上一段计算深度。」 | **默认就用这档。** 不含任何术语，机制说满了 |
| **加码档** | 「这个有形式化结论，ICLR 2024 有篇论文证明了：**T 步 CoT 的表达力等价于规模为 T 的布尔电路**。」 | 对方明显吃这一套、或已经在聊理论时 |
| **追问档** | 上面那段 AC⁰ 与奇偶性的解释 | **只有你真能讲的时候才亮** |

## 9. 核心结论

> **三者是对同一个条件分布动的三种手术：System prompt 定分布的底色，few-shot 钉分布的形状，CoT 把一次尖不起来的采样，拆成一串尖得起来的采样。**

CoT 单独被追问时的一句：

> **模型的层数是固定的，一次前向只有那么多串行计算。CoT 的本质是用额外的 token 去买计算深度；而且写出来的中间结果会进入上下文被回读，所以它同时还是一块外置的工作记忆。**

对方在聊理论、且你扛得住追问时，才加这一句（说法与边界见 7.5）：

> **这个有形式化结论——ICLR 2024 证明过，T 步 CoT 的表达力等价于规模为 T 的布尔电路。**

被问到安全时的一句：

> **system 高于 user，不是架构强制的，是训练出来的偏好。所有 token 走同一条通道——这就是提示注入没法在模型内部根治的原因。**
