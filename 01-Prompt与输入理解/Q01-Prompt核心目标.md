## ⚡ 30 秒速览（复习时只看这一块）

- **一句话回答**：Prompt 不改变模型，改变的是**模型从哪片条件分布开始采样**。核心目标是把目标 token 的分布压尖；而十倍的差距不是"模型更努力了"，是两个写法把它扔进了**两片不同的语料区**。
- **必须覆盖的关键词**：`条件分布` `分布尖锐 / 平坦` `没有"理解意图"这一独立步骤` `续写最像的下文` `选择进入哪个分布区` `prompt 是坐标不是指令` `措辞贬值 / 取舍升值` `context engineering`
- **上次的失分点**：
  1. **只答了一个问号。** "核心目标是什么"答了，"为什么差十倍"没答——而那半题**题库标准答案同样没答**，是白给的超车位置
  2. 答案只有一句，**没有对照例子**。"帮我写个请假邮件" vs "你是职场邮件助手…语气正式，200 字以内"，这一组对照本身就是半个答案

## 1. 题目原文

> Prompt Engineering 的核心目标是什么？为什么模型对同一件事，换个说法效果会差十倍？

## 4. 完整答案（面试可直接复述）

### 4.1 一句话定义

Prompt Engineering 的核心目标不是"把需求说清楚"，是**改变模型输出的条件分布**——让目标方向的概率变尖锐。

### 4.2 分层展开

**① 及格线：模型是条件概率生成器**

给什么输入，它就按条件分布往下接。写得模糊，概率分散到很多方向；写得精准，概率集中到目标方向。所以核心不是"哄模型"，是**把意图翻译成模型最容易接续的形式**。

**② 生产级：为什么换个说法能差十倍**

关键在于——**模型没有"理解你的意图"这个独立步骤。**

它做的事只有一件：**把你的输入当成一篇文章的开头，续写最像的下文。**

所以 prompt 真正干的活不是"传达需求"，是**选择模型进入哪一片分布区**：

| 写法 | 这个开头在语料里后面跟着什么 | 落进哪片区 |
| --- | --- | --- |
| 「帮我写个请假邮件」 | 各种随意的、口语的、长短不一的东西 | **宽而杂**的分布区 |
| 「你是职场邮件助手，写一封事假邮件，语气正式，200 字以内」 | 规范的、格式化的职场文书样本 | **窄而齐**的分布区 |

> **十倍的差距不是模型"更努力了"，是你把它扔进了另一个街区。**
> 同一个模型、两个 prompt，等效于**两个不同的条件分布**——差的不是执行质量，是**起点就不在同一片语料里**。

**③ 一句话收束**

> **Prompt 不是指令，是坐标。**

**④ 2026 年的追问：prompt engineering 是不是已经死了？**

> 「既然 prompt 这么重要，为什么业界都在说 prompt engineering 已死、context engineering 才是重点？」

**答法**：分清哪一半在贬值、哪一半在升值。

- **贬值的那一半 —— 措辞**。**凡是符号都可以被模型生成**，prompt 也是符号。所以"把 prompt 写好"这个技能本身正在被模型吸收掉——你可以让模型写 prompt、改 prompt、优化 prompt。
- **升值的那一半 —— 取舍**。没被吸收的是外面那圈：**每一轮往窗口里放什么、不放什么、工具返回怎么设计、记忆怎么外置**。这些是**结构决策，不是措辞决策**，模型替不了你做。

> **单条消息的措辞在贬值（因为可生成），窗口内容的取舍在升值（因为那是架构判断）。**
> **Prompt engineering 没死，它长大了改名叫 context engineering。**

### 4.3 加分项（说出来能拉开差距）

- **主动给出那组 prompt 对照**（请假邮件那两句）。抽象说法 + 一组具体对照 = 听起来像做过，而不是像读过。
- **把"分布区"这个说法接到别的题上**：分布平坦正是 [[Q04-幻觉成因与治理]] 里幻觉的种子；把一次平坦采样拆成多次尖锐采样正是 [[Q02-SystemPrompt与Fewshot与CoT]] 里 CoT 在做的事。**同一个词横跨三题，说明你有一套坐标系，而不是三段背诵。**
- **主动把 context engineering 的四根柱子报出来**（指令 / 检索 / 记忆 / 工具），说明你知道 prompt 只是其中一根 —— 详见 [[Q06-FunctionCalling与RAG]] 的基线核查。

## 5. 第一性原理（往下再挖一层）

- **本质约束**：模型的全部能力就是「给定前缀，输出下一个 token 的条件分布」。**你唯一能动的东西就是那个前缀。** 所以一切 prompt 技巧，本质上都只有一个动作：**改写条件**。
- **为什么"翻译意图"这个说法是错的**：它暗示模型那头有一个"理解"的接收端。实际那头只有一个条件分布。**没有接收端，只有条件。**
- **不这么想会怎样**：会去研究"怎么措辞更礼貌 / 更强硬"这类玄学，而不是去问"这个写法把模型放进了哪片语料"。后者可解释、可复现、可迁移到别的模型；前者不能。

## 7.5 查证记录（2026-08-28）

### ✅ 核实通过

| 说法 | 核实结果 |
| --- | --- |
| 模型按条件分布续写，prompt 即改写条件 | ✅ 自回归语言模型的定义性质，无争议 |
| "prompt engineering 已死 / context engineering 才是重点" | ⚠️ **行业共识性表述，不是研究结论**。与 [[Q06-FunctionCalling与RAG]] 基线核查查到的「上下文工程四柱」是同一件事的两种说法。可当框架用、当口径讲，**别说成"研究表明"** |

### ⚠️ 一条必须带上的诚实边界

**「模型没有理解意图这个独立步骤，只是续写最像的下文」——这个说法在"训练目标"这一层完全成立，但不要外推成"它内部什么都没在想"。**

> ✅ 已核实：Anthropic《On the Biology of a Large Language Model》（2025-03，transformer-circuits.pub，对象是 Claude 3.5 Haiku）用归因图追踪发现——**模型写押韵诗时会提前选定行尾的韵脚词，再倒着把整行写出来**。给出「He saw a carrot and had to grab it」时，模型在处理 "grab it" 阶段就已经锁定了 "rabbit"，然后照着这个结尾去写下一行。

**所以准确的表述是**：

> **训练目标是 next-token，不等于内部计算是"只想下一个 token"。**
> 「续写」描述的是**目标函数**，不是**内部机制**。

**为什么这条要写进来**：碰到懂可解释性的面试官，"它只是在续写、根本没在想"这句会被当场反驳。**带上这个限定反而更强**——你既知道机制层的解释，也知道这个解释的边界在哪。

### ➕ 本次新增

- 上面那条诚实边界（Anthropic 前向规划证据）
- 与 [[Q06-FunctionCalling与RAG]] 基线核查的**独立汇合**：出题人给的 context engineering 追问，和我在 Q06 基线核查里查到的「上下文工程四柱」是同一个框。**两条路径撞到同一个结论，说明这个框在 2026 年确实是共识而非小圈子说法。**

## 9. 核心结论

> **Prompt 不是指令，是坐标。它决定的不是模型"做什么"，是模型"从哪片分布里开始采样"。**

接住"prompt engineering 已死"这个追问的一句：

> **单条消息的措辞在贬值，因为它可生成；窗口内容的取舍在升值，因为那是架构判断。Prompt engineering 没死，它长大了改名叫 context engineering。**
