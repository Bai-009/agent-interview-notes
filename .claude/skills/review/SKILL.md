# 复习 = 你问我答（2026-09-06 用户定调）

> 用户原话：「复习的时候也不该去看你写的文档，应该通过这样的方式来」「我并不是不知道，而是没有被激发出来」。
> **档案是维护方的题库，不是用户的读物。** 整轮复习用户一个文件都不打开。
> 首次跑通：2026-09-06 Q11 九问 7/9，拦下的两处与记录预判的失分点完全重合（见 `_原始记录/2026-09-06-Q11九问验收.md`）。

## 0. 选题

- `$ARGUMENTS` 是题号（如 `Q11`）→ 复习该题。是主线名 → 走第 5 节。
- 留空 → 读 `00-索引/复习清单.md` 的弱点档案，把 🔴 / 🟡 各题列成一行（题号 · 上次复习日期 · 一句弱点），让用户挑；**不替他挑**。
- ⬜ 未作答 / 🔄 进行中的题**不进复习**（泄题红线，CLAUDE.md ③）。

## 1. 备题（用户看不到这一步）

读该题记录四处：⚡ 速览的「必须覆盖的关键词」与「上次的失分点」；第 6 节追问链（含 ☐ / ☑）；第 10 节最后一行；复习清单里该题那一行。

出题顺序：**① 上次的失分点 → ② 追问链里还是 ☐ 的 → ③ 速览关键词里还没被问到的。**

- 不照抄追问链的问法，改成**面试官口吻**，尽量接在用户上一句话上（「你刚说 X——那 Y 呢？」）。
- 每问备好判定依据（记录里的原句、数字、一手来源），**只用来判分，不提前说**。

## 2. 提问纪律（硬）

- **一次一问。** 不列清单，不并列两问；追一句也算一问。
- **不给提示。** 问题里不出现答案的关键词；数字和原句在用户答完之后才拿出来作确认。
- **用他的词。** 用户不写代码：说「软件」不说「客户端」，说「说明书」不说「schema」。用户对某个词卡住 → 先用他说过的话把那个词重新定义一遍，再把问题**原样再问一次**。
- **只答名词不算答完。** 「这时候需要渐进式披露」→ 追「具体怎么做的？」
- **中途不教新内容。** 查证带回来的新东西先记下，复习结束后再给。

## 3. 判分与拦截（硬）

- **按内容判，不按自评**（CLAUDE.md §5）。对的说清具体对在哪、比通常水准高在哪，一两句，不泛泛。
- **答错先拦，不给答案。** 说「拦一下」+ 一句为什么值得拦（如「这正是出题人犯过的错」），然后问一个**更小的问题**把他往前带（拆步）。每步只问一件事。
- **最多拆三步。** 三步后还到不了 → 直接给答案，记 ❌。
- 「不知道 + 我会去查什么」→ 记 ⚠️，不算错；「查什么」本身要评。
- 用户中途反问 → 先答他的反问（一两句），再把原问题拉回来，**不要顺着反问走远**。

## 4. 收尾（必做，顺序固定）

1. **记分表**贴给用户：`| # | 问 | 结果 |`。结果只有四种：✅ 自答 / ✅ 追一句后 / ❌ 拦下（拆 N 步）/ ⚠️ 不知道但知道查什么。表下一句：拦下的和记录里预判的失分点是否重合。
2. **掌握度**：全 ✅ 且无拆步 → 🟢；有 ❌ 或有拆步 → 🟡；❌ 过半 → 🔴。写明理由。
3. **归档**：`_原始记录/YYYY-MM-DD-Qxx-验收.md`——用户原话一字不改；维护方的问、拦、拆步按原样；结论性讲解压成一行。
4. **改记录**：徽章 `复习: N 次` `上次复习: 日期`；判定块加一条 📌；速览「上次的失分点」换成本次拦下的（首答的失分点括号保留）；第 6 节：✅ 自答的 ☐ → ☑，❌ 的退回 ☐；第 10 节加一行（x / y、拦下哪几处、拆了几步、归档链接）。
5. **改索引**：复习清单该题行补本次确认的弱点 + 徽章日期；掌握度变了 → 题库进度与 README 跟着改。
6. `python3 _工具/自检.py` 通过 → git 提交（中文 message，钩子自动推送）。

## 5. 串主线（统一复习第二轮）

`$ARGUMENTS` 是主线名（见 `00-索引/知识网络.md` 六条主线）时：不逐题，让用户**从头讲这条线**；维护方只做两件事——他停下时问「然后呢，这个接到哪一题？」；他说错时按第 3 节拦。记分按「线上的节点有没有被他自己接上」。归档同第 4 节；被讲到的每一题第 10 节各加一行，注明「串主线」。

## 6. 不做的事

- 不让用户读任何文件；不贴速览；不说「你可以先看看记录」。
- 不做到期提醒（CLAUDE.md §7）。
- 不在复习里补录首答、不改原始回答区。
