1. **性能**：五万个都过一遍不贵吗 → 逼出「几十亿次乘加 vs 五万次加法」的量级对比

3. **精度**：下一个字段一定固定吗 → 对方承认「**我上一条说得太绝对了**」，修正为「结构被强制，内容仍自由」

## 4. 完整答案（面试可直接复述）

### 4.1 三档强度：前两档是请求，第三档是物理

| 档位 | 做法 | 性质 |
| --- | --- | --- |
| 一 | prompt 里写"请输出 JSON" | **请求**。模型大概率照做（训练里见过无数 JSON），但随时可能加一句"好的，这是您要的结果："、用中文引号、最后少一个括号。**你在跟一个概率分布讲道理** |
| 二 | 给几个 few-shot 例子 | **更强的请求**。还是请求 |
| 三 | **在采样那一步动手**（约束解码 / schema 强制） | **物理限制**。和前两档不是程度差别，是**本质差别** |

### 4.2 机制：mask + 状态机预编译

**第一步 —— 屏蔽**

模型每一步吐出来的是词表里所有词的分数（几万到十几万个）。约束解码在采样器挑选**之前**，把「此刻不合法」的词的分数全部设成**负无穷**。采样器根本看不到它们。

具体例子，已经输出到：
```
{"name": "张
```
此刻合法的下一个 token：任何能接在字符串里的内容，或一个收尾的引号。而 `{`、`[`、一个新字段名——**JSON 语法不允许**，全被抹成负无穷。

**这个动作的性质**：不是让模型更**愿意**守格式，是**把「不守格式」这个选项从牌桌上拿走了**。输出不可能是非法 JSON——不是"很少"，是数学上不可能。

> 🔗 **认出这个形状**：这和 Codex 那张十一个格子的白名单是同一个动作——**不是拦坏的，是只放行能证明合法的**。**Default FAIL 在采样层的版本。**

**第二步 —— 为什么这不贵（追问一逼出的）**

「五万个都过一遍？」——**是的，真的过一遍。而且这不贵。**

关键在量级对比：
- 产生这五万个数字：模型刚做完**几十亿次乘加**（走完全部层）
- 屏蔽它们：对一个五万长的数组扫一遍改值 → **五万次加法**

几十亿 vs 五万，后者在总耗时里基本看不见。

> 烤一个蛋糕要一小时，切之前挑掉几块不能吃的要三秒。你不会因为"还要挑"就觉得不划算。

**第三步 —— 怎么知道哪些合法（这才是真正的技术点）**

如果每一步都拿语法规则挨个检验五万个 token——**那才是灾难**。真实实现不这么干。

**真实做法：生成开始之前，先把 schema 编译成一台状态机。**

schema 描述的合法 JSON 其实是一张有限的「路线图」。每个时刻你站在图上某个位置，从这个位置能往哪走，**是提前算得出来的**。所以开跑前把图走一遍，建好一张表：

```
位置 A → 允许这批 token
位置 B → 允许那批 token
```

运行时只需知道「我现在在哪个位置」→ **查表** → 拿到允许集合，其余全屏蔽。**没有五万次判断，只有一次查表。**

> **昂贵的活在开跑前干完了一次。** 这就是 Outlines 那类库在做的事。

> ✅ **查证确认，并且能把术语报得更准**：Willard & Louf,《Efficient Guided Generation for Large Language Models》(**arXiv:2307.09702**，Outlines 的论文)。
> 它的原话是把生成**重新表述为有限状态机的状态转移**，并据此**在语言模型的词表上构建一个索引**（an index over the vocabulary）；运行时在 **decoder 的 softmax 层屏蔽 logits**，抹掉那些会导致不匹配的 token。论文明确说这个做法 **"adds little overhead"**（几乎不增加开销）——正好印证了上面那笔量级账。
>
> 面试里把 **「FSM + 词表索引 + softmax 层 mask」** 三个词连起来说，比说"查表"专业得多。

### 4.3 两条设计代价（生产级，大部分人写 schema 时没意识到）

**代价一：字段顺序，就是推理顺序**

模型从左往右生成，**没法回头改**。所以这两个 schema 效果天差地别：

```jsonc
{"answer": ..., "reasoning": ...}     // ← 灾难
{"reasoning": ..., "answer": ...}     // ← 正确
```

第一个逼模型先把答案说出来再补理由——答案已经钉死了，后面的"推理"只能是**给结论找补**。这就是「先答后编」，而且**是你亲手用 schema 制造的**。
第二个让它先展开，答案在推理末尾自然落下。

> **一个字段的顺序，就是要不要 CoT 的决定。**

**代价二：必填字段会强迫幻觉**

schema 写着 `birthday` 必填 → 模型不知道张三生日时，**它必须填一个东西进去**。合法输出必须有这个字段，采样器不允许它跳过。

**你用 schema 强迫它编了一个日期。**

这是在结构层面**重演 [[Q04-幻觉成因与治理]] 的第三道工序**——又一次把"我不知道"的出口堵死，而且这次是**物理堵死，比训练偏好还硬**。

> **纪律：永远留不确定性的出口。一个没有"我不知道"选项的 schema，是在用工程手段制造幻觉。**

### 4.4 一条真实的性能代价：token 边界 ≠ 语法边界

这条恰好是「听上去很诡异」那个直觉真正指向的东西。

模型词表里可能存在 `age":` 这样**跨越语法边界**的组合 token。于是：模型本来想一口气吐 `age":`（一个 token，它最顺的写法），但状态机此刻只允许 `"`，**它被迫走一条训练时很少走的拼法**。

结果：**输出仍然合法，但模型被推离了熟悉的分布，质量可能下降。**

> **约束解码真实的代价不是慢，是你可能把模型逼进它不擅长的表达路径。** 这也是为什么严格 schema 有时反而让答案**变差**，而不只是变整齐。

**✅ 查证：这条不只是定性成立，有论文、有数字、还有一个反转。**

**规范引用**：Tam et al.,《Let Me Speak Freely? A Study on the Impact of Format Restrictions on Performance of Large Language Models》，Appier AI Research + 台湾大学，**EMNLP 2024 (industry track)**，arXiv:2408.02442。核心结论：**格式约束显著削弱推理能力，且约束越严，退化越大。**

**量级**：多项研究观察到——严格格式约束造成推理性能下降约 **10–30%**；限定 JSON / XML / YAML 输出使推理准确率下降约 **10–15%**。

**两条退化机制**（正好对上前面推的两条）：
1. **被迫在推理完成前就吐出 answer 字段** ← 就是 4.3 代价一
2. **分词歧义与分布偏移**，模型被推到分布外 ← 就是 4.4 token 边界错位

**⚠️ 但这里有个反转，必须记住，否则答案会偏：约束解码不是一律有害的。**

| 任务类型 | 约束的影响 | 为什么 |
| --- | --- | --- |
| **推理 / 生成类** | ❌ **掉 10–15%** | 中间推理步骤需要自由展开的空间，刚性结构把它挤没了 |
| **分类 / 选择类** | ✅ **反而提升** | 把输出限定在合法选项集里，**直接消灭了"选项写错"这一类错误**（在 DDXPlus 这类任务上 JSON mode 明显更好） |

> **所以正确的工程判断不是"schema 会伤推理，所以少用"，而是看任务形状：**
> **要模型"想"的时候，别用严格 schema 锁住推理路径；要模型"选"的时候，严格 schema 是纯赚。**

**缓解手段**（对应 4.4 那条代价）：
- **推理在前、结构在后**：让模型先自由输出推理，再进入受约束的结构化段（也就是把 4.3 代价一的解法制度化）
- **token healing**：微软 **Guidance** 库的做法——生成时**回退一个 token**，再约束首个新 token 必须以 prompt 末尾那个 token 为前缀，从而修复边界错位。
  为什么这个问题普遍？因为**约 70% 的高频 token 本身是更长 token 的前缀**——只要它出现在边界上，就会触发 token boundary bias。

### 4.5 confidence 字段：模型写的是编的，你算的才是测的（追问一逼出）

**如果这个数是模型自己写进 JSON 的，那它什么都没衡量。**

模型生成 `"confidence": 0.9` 里那个 `0.9`，走的是和生成日期**完全一样**的采样流程。**它没有任何通道能读到自己刚才那个日期的分布有多平。** 它在模仿"这种场合下人们通常写多少"。

所以「让模型输出 confidence 字段」本质是**表演**——你拿到一个看起来像概率的数字，背后没有任何测量。而且它继承全部原罪：RLHF 教过它自信，报的数普遍偏高，什么都写 0.85、0.9。

**真正的数只有一个来源：你的代码从 API 返回的 logprobs 去算，然后附上去。**

> **模型写的 confidence 是它编的；你算出来附上的 confidence 是测的。同一个字段名，两种完全不同的东西。**

**但 logprobs 有个陷阱**：token 概率测的是「下一个字该怎么写」，不是「这件事是不是真的」。
- **答案对但 logprob 低**：日期可以写成"3月12日"/"March 12"/"1985-03-12"，三种写法瓜分概率 → 测到的是**措辞的犹豫**，不是事实的犹豫
- **答案错但 logprob 高**：编出来的 API 名字一旦开了头，后面每个 token 都顺理成章 → **幻觉可以是高置信的**

**不确定性出口的强度排序（修正后）**：

| 强度 | 手段 | 为什么 |
| --- | --- | --- |
| **强** | `nullable` / 枚举加 `unknown` | **二值的、诚实的表态**，不涉及精度问题 |
| 弱 | confidence 粗档位 `certain\|likely\|uncertain` | 非用不可时的次选，粗颗粒**反而更抗噪** |
| ❌ | 0–1 浮点 confidence | **假精度**，模型写"0.73"纯属瞎凑 |

> 结构上那条判断不变：**字段的价值不在那个数准不准，在于它给了模型一条「不承诺」的合法路径。** 有了出口，「它选择走了出口」这件事本身就是真信息。

### 4.6 提示三的答案：双向翻译协议

| 方向 | 是什么 |
| --- | --- |
| **工具返回的结构化信封** | 把**确定性世界的信息翻译进概率世界**——让模型能"看见"成败 |
| **Structured Output** | 把**概率世界的输出翻译回确定性世界**——让代码能解析它 |

> **两个方向，同一道接口。**

这是自己写过的《两种坐标系》里那个"翻译协议"的完整形态——当时写到接口那里停住了，这就是那个接口的两个方向、各自的工程实现。

## 5. 第一性原理

- **本质约束**：LLM 的输出是概率性的，而代码是确定性的。两边要接上，只有两条路——**要么让概率端尽量守规矩（请求，前两档），要么在接缝处物理切断非法路径（第三档）**。前者永远有漏网率，后者没有。
- **为什么第三档是质变**：它把"格式正确"从一个**统计性质**变成了一个**类型性质**。前者需要下游写防御性解析，后者可以直接 `json.loads`。
- **代价的来源也是同一个**：你在概率端强行施加确定性结构，模型的分布就要为此变形——所以代价必然出现在**分布被扭曲**的地方（token 边界错位、必填字段强迫编造），而不是速度上。

### ➕ 本次新增（三条都能直接拉高答案水位）

1. **量化**：格式约束致推理退化 **10–15%**（严格约束下可达 10–30%），不再是"可能变差"这种模糊表述
2. **🔄 反转结论**：约束解码**只伤推理/生成类任务，对分类/选择类任务反而是提升**——因为它消灭了"选项写错"这类错误。原讲解只说了坏的一半

### 📌 最该记住的一条修正

原讲解的收尾是"严格 schema 有时反而让答案变差"。
**更准的版本是：**

> **约束解码是有方向性的——它拿走自由度。**
> **需要自由度的任务（推理）会掉分，不需要自由度的任务（分类/选择）反而受益。**

这句话把一条经验升级成了一条**可判断的选型规则**。

## 9. 杀手句

> **Structured Output 的本质不是"让模型输出 JSON"，是把格式约束从「请求」降级成「物理限制」——在采样前把非法选项抹掉，让违规不可能发生。而它的代价必须被设计：字段顺序决定推理顺序，必填字段会强迫幻觉。**

补一句留给追问的（4.4）：

> **约束解码真实的代价不是慢，是你可能把模型逼进它不擅长的表达路径。**

查证后可以再补一刀（这句是选型规则，含金量最高）：

> **约束解码是有方向性的——它拿走的是自由度。所以需要自由度的任务（推理）掉 10–15%，不需要自由度的任务（分类、选择）反而受益。问题从来不是"要不要上 schema"，是"这个任务需不需要模型自己想"。**
