## ⚡ 30 秒速览（复习时只看这一块）

- **一句话回答**：必须混合，因为嵌入是**有损压缩**——训练目标决定它保住高频主题词、销毁稀有精确符号（错误码/函数名/型号），而 BM25 的 IDF 恰好给稀有词最高权重：两者在**词的稀有度这根轴上强弱完全相反**，而检索里区分度最高的恰是稀有词。
- **必须覆盖的关键词**：`有损压缩` `稀有度互补` `RRF（按排名融合）` `否定盲区` `语义稀释` `parent-child` `bi-encoder / cross-encoder` `recall@k 天花板` `分块不可逆`
- **上次的失分点**：① 说了「设权重 α 和 1−α」——**BM25 无界、余弦有界，量纲不可比**，加权求和实际是 BM25 主导；工业做法是 RRF 按排名融合。② 题眼只接住一半：说出「向量检索看不见字面精确」，没说出**为什么**（压缩保什么销什么由训练目标决定）以及**最有区分度的词恰是丢得最干净的**。
- **答题骨架**：① 嵌入 = 有损压缩，销毁稀有符号 → ② BM25 的 IDF 反向 → 稀有度互补 = 必须混合 → ③ 融合用 RRF（排名可比，分数不可比）→ ④ 分块张力（小=方向纯 / 大=上下文全）与 parent-child，分块**不可逆** → ⑤ bi/cross-encoder 的分层经济学（被逼的，不是设计出来的）→ ⑥ 错误只往下游传，recall@k 是天花板

## 4. 完整答案（面试可直接复述）

### 4.1 一句话定义

Embedding 把文本压成定长向量、向量数据库按相似度找回它们——这一对负责 RAG 的「召回」。但嵌入是一次**有损压缩**，压缩销毁掉的信息决定了检索策略的每一条设计：混合、分块、重排，全是在补偿压缩的损失。

### 4.2 为什么必须混合：两条方向相反的曲线

嵌入模型的训练目标是「让语义相似的文本靠近」。语义相似度主要由高频、承载主题的词决定，所以向量里**保留的是主题**；而稀有的精确符号——订单号、错误码、函数名、型号、人名、日期——在训练语料里出现太少，对损失函数的贡献接近零，模型没有动力为它们保留清晰的签名，**它们在向量里被平均掉了**。

BM25 的核心是 IDF：**词越稀有，权重越大。**

| 词的稀有度 | 嵌入保留它的程度 | BM25 给它的权重 |
| --- | --- | --- |
| 高频（「系统」「处理」「数据」） | 强 | 几乎为零 |
| 稀有（`ERR_5012`、`parse_config`） | 接近零 | 最高 |

所以必须混合的原因不是「两路都不错，都用保险」，是**两者在稀有度这根轴上强弱完全相反**。更进一步：检索里**区分度最高的词恰是最稀有的那些**（搜 `ERR_5012` 一个词锁定文档，搜「系统处理数据」一万篇都沾边）——对精度贡献最大的那类词，正好是嵌入丢得最干净的那类。

**实证**：EntityQuestions（EMNLP 2021）用最简单的实体问题（「Arve Furset 出生在哪」）测出稠密检索在稀有实体上大幅落后 BM25，且数据增强修不好——「稀有符号是嵌入的结构性盲区」不是经验之谈，是有对照实验的。

**第二个结构性盲区：否定。** 「关于 X」和「不关于 X」余弦相似度极高；「增长」和「下降」经常挨得很近——分布式语义看不见「不」。查证补充（NevIR，EACL 2024）：否定其实是**整个第一段检索的盲区**——BM25 对否定同样无感（「不含 X」里的 X 照样命中），测评里多数检索模型在否定对比对上**不如随机排序**；架构排序是 cross-encoder > 晚交互 > 双塔/稀疏。所以带否定、带排除条件的查询，主要止损点在 **rerank 层**，混合检索救不了它。

### 4.3 怎么融合：RRF，按排名不按分数

加权求和（α 与 1−α）不可行：BM25 分数**无界**（3 也可能 47，随词频、文档长度、语料规模变），余弦**有界**（−1 到 1）。两个量纲不可比，加权和实际由 BM25 主导，且换个语料权重就得重调。

RRF（Reciprocal Rank Fusion）绕开而不是解决这个问题——**不看分数，只看名次**：

```
最终分 = Σ 1 / (k + 该文档在第 i 路的排名)      k 通常取 60
```

名次天生可比。k=60 是平滑项，防止第一名权重压倒性地大——这是原论文（SIGIR 2009）基准上平均表现最好的取值，很稳，几乎不用调。

### 4.4 分块：唯一不可逆的一步

**embedding 想要小块，生成想要大块。** 根子在「一个向量」：不管输入 10 个词还是 500 个词，出来的都是同一个定长向量。块大了，多个主题被压成**方向的合力，指向一个谁都不是的地方**（语义稀释）；块小了，「这个限制是 30 天」没有主语，向量指向哪都不是。两头都塌，中间才有甜区。

- **parent-child** 跳出这个权衡：**小块负责被检索到，命中后返回父块给模型读**——检索用纯净的方向，生成用完整的上下文，各拿各要的尺寸。
- **overlap** 是防止句子被切在边界上的粗暴补丁；真正的解法是**按结构切**（标题/章节/函数边界），切在语义的接缝上，不是第 512 个 token 上。
- **分块是整条链路上唯一不可逆的一步。** 召回漏了可以加路数、重排错了可以换模型，但分块切碎的语义，下游任何环节都补不回来。调 RAG 从换嵌入模型、调 top-k 开始的人，都在下游打转——真正的病常在分块。

### 4.5 Rerank：分层是被逼的，不是设计出来的

| | bi-encoder（双塔，召回用） | cross-encoder（交叉编码，精排用） |
| --- | --- | --- |
| 结构 | query 与文档**各自**编码，从头到尾没见过面，最后比一个距离 | query 与文档**拼在一起**过完整注意力，文档每个词都看得到查询每个词 |
| 能否预计算 | 能——文档向量离线算好存起来 | **不能——必须知道 query 才能开始算** |
| 规模 | 百万级 | 几十条 |
| 精度 | 一般：文档被编码时不知道谁来查，只能准备「对所有查询都还行」的通用表示，**通用 = 对任何具体查询都不最优** | 高：能判断「这个词是不是在回答那个问题」 |

先用便宜的从一百万里捞五十条，再用昂贵的把五十条排对。**不是「先粗后精稳妥」，是精的那个物理上不可能扫全库。** 这个漏斗形状在本仓已第三次出现：约束解码把检查前移（Q05）、agentic search 的宽搜窄读、这里的召回+精排——同一套分层经济学，换了三种材料。

### 4.6 链路与指标：错误只往下游传

```
分块 → 向量化(bi-encoder) → 索引(HNSW) → 召回(top-k) → 重排(cross-encoder) → 生成
```

- 分块切碎 → 后面全废；召回没捞到 → 重排救不了（它只能排拿到的那五十条）；重排排错 → 生成必然基于错料。
- 指标分层：召回层看 **recall@k**（该有的进没进候选），重排层看 **precision@5**（对的排没排到前面）。
- **recall@k 是天花板**：它是多少，系统上限就是多少。overlap、多路检索、HNSW 的精度参数，全是在抬天花板——天花板漏了，下游无解。HNSW 本身是**近似**最近邻（为了快接受偶尔漏掉真最近的），是天花板上一个很少被注意的漏点。

### 4.7 四问的答案（地基层）

1. **为什么 embedding 想要小块**——见 4.4：不是「小块更精细」，是「小块的向量方向不被污染」。
2. **HNSW vs bi-encoder**——不同环节：**bi-encoder 造向量（模型），HNSW 找向量（索引结构）**。一百万个向量里找最近的 50 个，暴力算距离要一百万次，HNSW 用分层图在几十次比较里找到近似最近的那批。
3. **cross-encoder**——见 4.5：慢和准是同一个原因（必须看到 query 才能算，所以不可预计算）。
4. **交叉熵**——与 cross-encoder 无关，只是中文都带「交叉」。它是预训练的全部目标函数：`-log(正确 token 的概率)`。概率越低惩罚越大且加速变大，训练优先修「错得最离谱」的地方。**「模型只学下一个 token 的分布」里「学分布」三个字的数学形式，就是它**（接 [[Q01-Prompt核心目标]] / [[Q04-幻觉成因与治理]]）。

### 4.8 代价与边界（什么时候不该上向量检索）

- **语料满是精确标识符**（代码库、日志、工单号）：嵌入的结构性盲区正好压在语料的信息主体上，字面路（grep/BM25）为主，向量做补充甚至不上。
- **运维与信任成本**：[[Q06-FunctionCalling与RAG]] 已推过——放弃向量索引的动力主要是安全/隐私/索引陈旧/可靠性，**三条与召回率无关**。语料小到能整读、或更新频繁到索引永远陈旧时，不建索引反而是对的。
- **带否定/排除条件的查询占比高**：第一段检索（向量与 BM25 都）不可靠，必须靠 rerank 层止损，预算里要给 cross-encoder 留位置。

## 5. 第一性原理

**整题从一个事实推出：嵌入是有损压缩，而压缩保什么、销什么，由训练目标决定。**

- 训练目标是语义相似 → 保主题、销稀有符号 → 稀有符号恰是区分度之源 → **必须补一路按稀有度加权的字面检索**（混合）。
- 定长向量 → 块越大方向越被平均 → **检索与生成对块尺寸的需求相反** → parent-child 把两个需求解耦。
- 压缩发生在「不知道谁来查」的时刻 → 通用表示对任何具体查询不最优 → **必须有一个见过 query 的模型兜底**（cross-encoder）→ 它不可预计算 → 分层漏斗是物理结果。
- 链路串行且信息只减不增 → **错误只往下游传** → 最上游的分块不可逆、召回是天花板。

不这么做会怎样：纯向量检索的系统，在错误码、函数名、否定查询上**结构性失败**——不是效果差一点，是那类信息在向量里根本不存在。

## 6. 追问链

| 可能的追问 | 我该答什么 | 自查 |
| --- | --- | --- |
| BM25 分数为什么无界？ | 它是词频、IDF、文档长度归一化的加和，随查询词数和语料统计变，没有上界——这正是不能与余弦加权求和的原因 | - [ ] |
| RRF 的 k 起什么作用？ | 平滑项：k 越小头名权重越尖，k=60 是原论文基准上的稳健取值，几乎不用调 | - [ ] |
| 除了余弦还有什么相似度？ | 点积与欧氏距离；向量归一化后余弦与点积等价，很多嵌入模型直接按归一化后点积训练 | - [ ] |
| HNSW 牺牲了什么换速度？ | 精确性——近似最近邻，可能漏掉真最近的；ef/M 参数在 recall 与延迟间换，属于召回天花板的一部分 | - [ ] |
| chunk 512-1024 是定律吗？ | 是经验带不是定律：公开测评里更小的结构化块（200-400）常在检索指标上更好，且查询类型决定（事实型偏小、分析型偏大）——真正的原则是切在语义接缝上 | - [ ] |
| HyDE 为什么在清单里、你却不展开？ | 零样本场景的技术：让模型先生成假想答案再拿它去检索，把 query-文档不对称变成文档-文档对称；代价是每查询多一次生成，2026 年生产默认管线（混合+rerank+查询改写）里不是标配 | - [ ] |
| 否定查询怎么办？ | 第一段检索（向量与 BM25）都看不见否定，主要靠 cross-encoder rerank 止损；查询改写把「不含 X」转成结构化过滤条件更彻底 | - [ ] |

## 7.5 查证记录（2026-08-28）

### ✅ 核实通过

| 讲解中的说法 | 核实结果 |
| --- | --- |
| RRF 公式与 k=60 | ✅ Cormack, Clarke & Büttcher, SIGIR 2009。k=60 即原论文基准上平均表现最好的取值（论文写作 C=60） |
| 「稀有精确符号是嵌入盲区」 | ✅ 有实证：EntityQuestions（Sciavolino et al., EMNLP 2021, arXiv:2109.08535）——稠密检索在稀有实体问题上大幅落后 BM25，数据增强修不好 |
| 「否定是嵌入盲区」 | ✅ 且比讲解说的更广：NevIR（Weller et al., EACL 2024, arXiv:2305.07614）2,556 对否定对比文档，多数 IR 模型**不如随机**；cross-encoder 最好、双塔与稀疏最差 |
| HNSW 是近似最近邻索引结构 | ✅ Malkov & Yashunin, arXiv:1603.09320（TPAMI 2020），分层图、对数级复杂度、可调 recall/速度 |
| bi-encoder / cross-encoder 结构差异 | ✅ 双塔范式的代表是 Sentence-BERT（arXiv:1908.10084）；BERT cross-encoder 重排的代表是 monoBERT（Nogueira & Cho, arXiv:1901.04085）。**bi-encoder 是架构不是新算法**——追问二的混淆已澄清 |
| 交叉熵 = -log(正确 token 概率) | ✅ 标准定义，预训练目标函数 |
| HyDE 在题库清单里 | ✅ Gao et al., arXiv:2212.10496（ACL 2023）：生成假想文档再检索，零样本设定下超过无监督稠密检索基线 |

### ➕ 本次新增（查证带回来的增量）

- **否定盲区的完整版**：NevIR 显示 BM25/稀疏路对否定同样失明——所以「混合检索」补不了否定，**rerank 才是否定问题的主要止损点**。讲解把否定归为「嵌入的第二盲区」，准确的说法是「第一段检索的共同盲区」。
- **chunk 甜区的实证校准**：Chroma 技术报告《Evaluating Chunking Strategies for Retrieval》（2024-07）实测：策略间 recall 差距可达 9%，结构/语义感知的 200-400 token 块常优于固定 512；2025 年多数据集分析（arXiv:2505.21700）进一步显示**最优块长随任务型变**（事实型 256-512、分析型 1024+）。「512-1024」是经验带，不是定律。
- **归一化后余弦 ≡ 点积**——补上「我就知道余弦这一种」的缺口。

### 📌 用词校准

- 「余弦相似度实际挤在 0.7～0.9」——**随模型而变的经验描述**，不同嵌入模型分数带完全不同，不要当结论引用；结论只需要「有界 vs 无界」。
- 「k=60 几乎不用调」成立，但出处要说对：它是**原论文基准上的最优平均值**，不是理论推导。
- 「嵌入的第二个结构性盲区：否定」→ 校准为「第一段检索的共同盲区」（见上）。

## 7.6 基线核查（2026-08-28 · 随首答一并核查）

> 讲解的机制层（压缩/互补/分层）放在 2026-08 依然是对的。落后点在「实现层的选项已经变多」：

1. **双塔与交叉之间出现了第三个点：晚交互（late interaction / ColBERT 系）。** 文档侧按 token 存多个向量（可预计算），查询时做 token 级 MaxSim——比单向量表达力强、比 cross-encoder 便宜，NevIR 的否定榜上也恰好排在两者之间。讲解的二分法（双塔/交叉）是主干，但被追问「中间有没有折中」时要接得住。〔形态①实现层翻代〕
2. **「块小丢上下文」有了 parent-child 之外的两条新路线**：Contextual Retrieval（Anthropic 2024-09，入库时给每块预写一段上下文说明再嵌入）与 Late Chunking（Jina, arXiv:2409.04701——先整篇过长上下文嵌入模型、再在 token 向量层面切块）。三条路线解同一个张力：**让小块带着大块的语境进向量**。〔形态①〕
3. **字面路本身也在进化：学习型稀疏（SPLADE 系）。** BM25 的「稀有度权重」被做成可学习的词表扩展，稀有度互补这条轴正在被工程手段推动——把 BM25 当成字面路的终点，就是把变量当常量。〔形态②〕
4. **HyDE 的位置要说准**：零样本时代（2022）的技术，解决「无标注、query 与文档语域不对称」；2026 年生产默认管线是混合+rerank+查询改写，HyDE 不是标配（每查询多一次生成的延迟）。这一判断是工程共识，非论文结论。〔形态①〕
5. **考法本身在漂移**：本题是单跳 pipeline 题；2025-2026 的考法趋势向 agentic/多跳检索走（模型自己决定查什么、查几轮）。平衡的另一面已在 [[Q06-FunctionCalling与RAG]] 查证过：**经典 RAG 因可预测仍是强默认**——两条都要说，不偏一边。〔详见 [基线核查台账](../00-索引/基线核查台账.md) 的「题目集合漂移」一节〕

## 9. 核心结论

> **混合检索不是「两路都用求保险」——嵌入是有损压缩，训练目标让它保主题、销稀有符号，而 BM25 的 IDF 恰好给稀有词最高权重：两者在稀有度这根轴上强弱完全相反，而区分度最高的恰是稀有词。融合按排名（RRF）不按分数，因为 BM25 无界、余弦有界，量纲不可比。整条链路里，分块是唯一不可逆的一步，recall@k 是天花板，rerank 只能在天花板下面排序。**
