## ⚡ 30 秒速览（复习时只看这一块）

- **一句话回答**：Agent 的自主性不来自模型会规划，而来自**「贪心的一步」被放进一个会把结果拼回去的循环里**——工具是请求权（执行权在外部代码），知识是每轮重拼进上下文的 tool_result，计划是一份被反复重读的文本而不是被持有的意图。
- **必须覆盖的关键词**：`请求权 vs 执行权` `stop_reason 协议` `end_turn ≠ 任务完成` `每轮失忆 / 重拼上下文` `贪心的下一步` `计划 = 被重读的文档` `建议性上下文 vs 约束性状态` `todo = 被跟踪的状态`
- **上次的失分点**（2026-09-06 复习）：**计划要变成能勾的清单才能对账**——「验收标准」只验结果，不验第 20 步偏没偏；外面拿「勾掉的项」和「实际工具调用」比，勾本身不可信但可对账。**问号说判断仍在**（「有验收标准？」「强制停止？」「概率发挥？」）。（首答的失分点：题干并列三样只答了工具——**复习已不再犯**；把判断包装成疑问——**仍在**。）
- **答题骨架**：① 工具：tool_use 是请求不是执行，end_turn 不是通行证，验证有否决权 → ② 知识：tool_result 拼回下一轮输入，模型每轮失忆 → ③ 规划：默认只有贪心下一步，计划的连续性在文本里；plan 文本是建议性的，要管用就变成被跟踪的状态（todo/文件） → ④ 收束：自主性 = 贪心一步 × 拼回结果的循环

## 4. 完整答案（面试可直接复述）

### 4.1 一句话定义

Agent = 一个无状态的模型 + 一个会把结果拼回上下文的外部循环。工具、知识、规划三样东西没有一样住在模型内部——**工具是模型的请求权、知识是每轮重拼的输入、规划是一份被反复重读的文本**，把它们接在一起的是 harness，不是模型。

### 4.2 工具：模型只有请求权，没有执行权

- 模型与 harness 之间是一层 **stop_reason 协议**：`tool_use` 不是「模型执行了工具」，是「模型请求执行」——真正跑的是外面的代码；`end_turn` 不是「任务完成」，是「我这段话说完了」。
- **end_turn 不是通行证**：外部代码有资格不接受这个声明——对结果做验证，不过就把失败证据拼回 context 再调一轮。完成与否的判定权在验证器，不在模型的自我声明（[[Q04-幻觉成因与治理]] 的验证器思路：模型自报不可信，错误要可检测）。
- 协议全集（2026-08 现行 7 种，见 7.5）：`end_turn` / `max_tokens` / `stop_sequence` / `tool_use` / `pause_turn` / `refusal` / `model_context_window_exceeded`——harness 对每一种都要有预案，这本身就是「四层停止」问题的入口。

### 4.3 知识：不是注入模型，是重拼上下文

- 工具结果以 `tool_result` 的形式**拼进下一轮输入**。模型每一轮都是失忆的——API 无状态，你每次都在重新拼一份「你之前经历了这些」给它看。
- 所以「Agent 有记忆」是个错觉：**上下文是伪造的记忆**——它不是模型「记得」，是 harness 每轮重新递给它的文本。检索（[[Q07-Embedding与检索策略]]）、记忆文件、tool_result，全是同一件事的不同来源：往这份重拼的输入里放什么。
- 直接推论：循环越长，历史越占窗口，[[Q03-Token与上下文窗口与上下文腐化]] 的腐化就越严重——「知识」会被自己的执行痕迹挤出去。这就是压缩/记忆管理（Q15）存在的原因。

### 4.4 规划：默认不存在，存在的是贪心的下一步

- 默认循环里，**模型没有任何机制能持有一个跨轮的计划**。每一轮它只做一件事：看当前上下文，输出下一个动作。严格说循环里没有「计划」，只有一连串各自独立的、贪心的下一步。
- 看起来像有计划，是因为上下文里留着前几轮的痕迹——它读到「我刚才搜了 A、读了 B」，接出一个像「第三步」的东西。**计划的连续性不在模型里，在上下文的文本里。**
- plan mode 的实现就是把这件事显式化：先让模型生成一份计划文本 → 固定在上下文里 → 之后每轮重读。**计划是一个被反复重读的文档，不是一个被持有的意图。**
- 实际后果：**模型可以偏离自己写的计划，而且不会有任何东西报警**——计划对它是**建议性的上下文**，不是**约束性的状态**。
- 所以生产做法是把计划从「一段文本」升级成「一个被跟踪的状态」：写进文件、每步勾掉一项、每轮把当前状态重读进来——「到哪一步了」不再依赖模型记得，而是有外部的东西在记账。Claude Code 的 todo 清单就是这个（Anthropic 自己的工程博客把它归为 structured note-taking / agentic memory，见 7.5）——它是 [[Q02-SystemPrompt与Fewshot与CoT]]「状态外置」从 CoT 最小版到工程版的样子。

### 4.5 收束：自主性住在循环里

三根柱子拼起来：模型贡献的只有「看上下文 → 出下一步」这一个能力；**把下一步的结果拼回去、决定停不停、验证过不过，全是 harness 的代码**。所以「Agent 如何自主运行」的真答案不在模型侧在循环侧——这也是为什么 2026 年的考法从「会不会 ReAct」漂移到了「harness 内部怎么做」。

### 4.6 代价与边界

- **偏离无报警**是默认循环的固有代价：凡是「必须被遵守」的东西（预算、步数上限、禁区），都不能只写成上下文文本，要落在代码层（[[Q06-FunctionCalling与RAG]] 的主轴：这个决定放代码里还是模型里）。
- **停止问题本题只覆盖了 stop_reason 这一层**——模型自己停（end_turn）、协议停（max_tokens / 窗口超限）之外，还有验证器判停、预算/步数强制停等外层。出题人点名的「四层停止」完整框架尚未推导，挂待查。

## 5. 第一性原理

**根源只有一条：模型是个无状态的条件分布**（[[Q01-Prompt核心目标]]）。一次前向消费一段上下文、产出一段输出，请求之间什么都不携带。

- 无状态 → 记忆必须外置 → 知识 = 每轮重拼的输入（伪造的记忆）
- 无状态 → 意图无处存放 → 计划 = 上下文里的一段文本 → 建议性，不是约束性
- 概率采样 → 自我声明不可信 → 完成判定必须外置 → 验证器 + 外部循环的否决权
- 三条合起来：**Agent = 状态外置 + 结果回拼的循环 + 外部验证**。模型没变聪明，是循环让贪心的一步串成了任务。

不这么做会怎样：把计划、进度、完成判定留在模型「内部」的系统，第一次长任务就会偏航且无人报警——不是模型不好，是那里根本没有存放这些东西的地方。

1. **「计划外置为被跟踪状态」已经产品化。**〔接：讲解里的 todo 清单〕讲解推到「写进文件、每步勾掉」为止；生产上这已是一族成熟工具，全是「知识 = 每轮重拼进上下文」这一条的不同用法：**structured note-taking**（todo / 笔记文件——就是讲解点名的那个）；**memory tool**（让模型自己读写窗口外的记忆文件，要用时再拼回来）；**compaction**（窗口快满时把历史摘要成一段、开个新窗接着跑——重拼上下文的极端形式：这回拼进去的是摘要，不是原文）；**tool result clearing**（把很多轮之前的工具原始返回从历史里清掉——既然每轮都在重拼，旧结果就没必要每轮都占位）。与 [[Q06-FunctionCalling与RAG]] 上下文工程四柱的「记忆」柱直接咬合。〔形态①实现层〕
2. **单 turn 内的「规划痕迹」在变长。**〔接：[[Q02-SystemPrompt与Fewshot与CoT]] 的「CoT 用 token 买串行深度」+ 本题的 tool_use 循环〕早先的形态是「想一段 → 答完」；现在的模型可以在**一次请求内**「想一段 → 调工具 → 拿到结果接着想 → 再调」——思考块穿插在工具调用之间（interleaved thinking），单次请求内的推理-动作链条比 ReAct 时代长得多。但注意它改的是**单 turn 内能走多远**（变量）；**跨请求失忆没变**（常量）。把这两个分清，正是台账形态②的自查。〔形态②〕
3. **本题的考法本身就是「题目集合漂移」的例证**：题库版答案停在 ReAct（2023），出题人直接宣布不用理会——2026 年这题考的是 harness 内部（控制权/状态/停止），与台账记录的漂移方向（Harness Engineering、Loop Engineering）完全一致。

## 9. 核心结论

> **Agent 的自主性不来自模型能规划，而来自「贪心的一步」被放进了一个会把结果拼回去的循环里。计划、记忆、进度，全都不在模型内部——它们是每一轮被重新递给它的文本；所以凡是必须被遵守的东西，都不能只是文本，得变成外部被跟踪的状态。**
