## 4. 完整答案（面试可直接复述）

### 4.1 一句话定义

**漂移不是「忘了」，是「被压过去了」——上下文里没有「约束」这种东西，约束和普通文本都是 token，一起参与注意力竞价。** 治理必须分层：外置解决「还在不在」，只有不经过模型的执行前检查才解决「在但没照做」。**工具幻觉是同一件事的另一面：schema 管形状不管内容，内容层只能靠校验、出口与采样。**

### 4.2 前半题：漂移

**① 两种病因，治法完全不同**（答题骨架）

| 病因 | 是什么 | 例子 |
| --- | --- | --- |
| **一：那句话不在了** | 被压缩掉、被截断、被滑动窗口挤出去 | 第 3 轮的「别动数据库」在摘要器眼里最像闲聊，压缩时最先被优化掉 |
| **二：那句话还在，但被压过去了** | 十个 token 面对四万五千个 token 的近期语境，最近的内容天然占优 | 第 38 轮它就在上下文里，模型照样动了数据库 |

**第二种才是主戏。** 根子上的原因：上下文里没有「约束」这种东西——约束和普通文本都是 token，一起参与注意力竞价，没有哪句话自带更高权限（[[Q02-SystemPrompt与Fewshot与CoT|Q02]]：角色层级是学出来的偏好，不是架构强制）。Claude Code 官方文档自己的说法：上下文接近装满时，模型会开始「忘记」早先的指令；CLAUDE.md 写得越臃肿，模型越会忽略你真正的指令。

**② 三层治法，每层咬住一种病因**

| 层 | 治什么 | 做法 | 经不经过模型 |
| --- | --- | --- | --- |
| **软约束层** | 提高遵守概率 | system prompt、CLAUDE.md、plan 文件、把约束重新放到最近位置 | **经过**——是软边界，提高概率，不保证 |
| **状态外置层** | **病因一** | 把「必须活过四十轮的东西」从对话历史搬到文件里，每轮重新读进来 | 读进来之后仍经过模型 |
| **硬约束层** | **病因二** | hook、gate、权限、上限：执行前的确定性检查 | **不经过**——不参与竞价、不被压缩、不随会话衰减 |

**状态外置的三条理由**，一条比一条重要：
1. 对话历史只增不减，**文件可以改**——发现判断错了能改掉；
2. 对话会被压缩，**文件不参与压缩**——「别动数据库」这种话在摘要器眼里最像闲聊，最容易被优化掉；
3. 进程死了，**文件还在**。

一手例子：Anthropic 的多 Agent 研究系统里，主 Agent 第一件事是把计划写进 memory——原文的理由是「if the context window exceeds 200,000 tokens it will be truncated and it is important to retain the plan」。

**③ 天花板——这题的深度所在**

> 常见的记忆方案默认一个假设：**只要记忆被注入上下文，模型就会遵守它。这个假设不成立。**
> **外置解决「还在不在」，不解决「在但没照做」。**

所以「把约束重新放到最近的位置」是有效的——近因确实提高概率——但它**还是经过模型**。要保证「别动数据库」，就得让这句话变成一条**执行前的检查**：模型发出的每一次工具调用先过一道不读文本、不做判断的关卡。Claude Code 官方文档的原话：CLAUDE.md 里的指令是**建议**（advisory），hook 是**确定性的**（deterministic）——「never edit .env」写在 CLAUDE.md 里是请求，写成 PreToolUse hook 才是执行。

> 💡 复习时用户先答了软招、被问「经不经过模型」才改口。这个顺序值得记住：**面试里先说硬的**，再说软的是补充。

### 4.3 后半题：工具调用的幻觉

**① schema 管形状，不管内容**

| schema 彻底解决的（采样时非法选项直接被抹掉，[[Q05-StructuredOutput\|Q05]]） | schema 一个都拦不住的 |
| --- | --- |
| 格式非法 | **调错工具**——`delete` 和 `read` 同样合法 |
| 字段缺失 | **参数值是编的**——一个不存在的文件路径，完全是合法字符串 |
| 工具名不存在 | **压根没调工具，却在文本里写出「工具返回的结果」** |

用户的话：**能防住 key 写错，防不住 value 里的幻觉。**

**② 反转：schema 越严，越逼出幻觉**

必填字段 + 模型不知道 = 采样器不允许它跳过 = **它只能编一个格式正确的值**。这是「schema 管形状不管内容」的极端形式：形状被强制到底，内容只能编。解药是**留空出口**（[[Q04-幻觉成因与治理|Q04]] 那条「必填字段强迫幻觉 → nullable 出口」）——允许它说「我做不到」，转人工，而不是硬填一个值。

> ⚠️ 复习时用户答成了「限制死了会变笨」。那是 [[Q05-StructuredOutput|Q05]] 的另一条（约束解码让推理任务掉一截），是真的，但答的是性能不是幻觉。**两条都要会，别混。**

### 4.4 内容层四招（用户贡献 · 出题人转述）

在一个**没有免费验证器**的领域（文档抽取没有编译器和测试），用户当初的做法：

**① 校验器**：把领域知识编码成确定性判据（pH 落在 0–14），配重试上限，留「我做不到」的出口。
**边界必须说准**：校验器只抓「离谱」，抓不住「合理但错」——文档写 7.2、模型抽成 6.8，完美通过校验，而且错了。所以它的作用是**把明显错的挡在外面**，不是保证正确；「合理但错」只能靠抽样人工复核、交叉验证（同一字段从两处各抽一次，对不上就报警），以及下面第 ③ 招。

**② 干净上下文重试，不带反馈**。为什么不能在原上下文里说「你上次超范围了，再试」——模型的训练目标是**给出一个能被接受的回答**。你告诉它超范围，在它的分布里最像「正确续写」的不是重读文档，是**换一个落在范围里的值**。6.8 比 12 更像一个能被接受的 pH。你等于把答案范围泄露给了它。

> **把抽取错误变成了编造。**——这句说明你不只知道会出错，你知道错误会怎么变形。抽取任务的正确答案在文档里，不在合理区间里；反馈提供的是一个错误的锚点。

**③ 三次干净重开 = 三次独立采样**。三次都 12 → 模型稳定地读出同一个东西（值怪也先看文档，说不定文档真写错了）；三次 12 / 6.8 / 7.5 → 它在猜，这条必须人工。**这个信号是从外面测出来的，不是模型自报的**——自报的 confidence 是编的（[[Q04-幻觉成因与治理|Q04]]），测出来的才是真的。「重试直到通过」和「多次采样测稳定性」在代码上很像，在含义上完全不同。

**④ 留空出口**：见 4.3 ②。四招合起来：**校验器挡离谱、留空防硬填、干净重试防编造、多次采样测确定性**——四招没有一招指望模型自觉。

## 5. 第一性原理（往下再挖一层）

**本质约束：模型是纯函数，上下文是它的全部世界，而上下文里只有 token。**

1. 模型每轮失忆（[[Q08-Agent自主运行|Q08]]：记忆是每轮拼进去的）→ 任何「约束」要被看见，就得每轮出现在输入里 → 一旦出现在输入里，它就和其他 token 一起竞价（[[Q03-Token与上下文窗口与上下文腐化|Q03]]）→ 票数随轮次稀释是必然，不是 bug。
2. 所以**经过模型的措施只能改概率**：提醒、外置、放到最近位置，都在同一条曲线上——曲线更高，但仍是曲线。
3. **要一条水平线，就得离开模型**：hook 在执行前拦，沙箱在内核里拦（[[Q11-MCP与Skill|Q11]]），验证器在结果上拦。它们的共同点只有一个：不读文本、不被说服。

**不这么做会怎样**：只靠提醒 → 遵守率随会话变长下降，第 38 轮总会来；只靠外置 → 「别动数据库」永远在文件里，也永远只是几个 token；只靠 schema → 形状越严，编造越多。

**收一句**（模块三总判据，本题第三次出现）：**判断一个措施是软是硬，只问它经不经过模型。**

## 8. 关联

- **物理底座**：[[Q03-Token与上下文窗口与上下文腐化|Q03]] —— 注意力零和竞价：早期约束的票数被近期 token 稀释，是本题主病因的机制；**这是同一条原理的第五处落点**（Q07 rerank、Q09 主链宝贵、Q10 约束被压过去、Q11 工具越多选得越差）。
- **直接父题**：[[Q08-Agent自主运行|Q08]] —— 「上下文是伪造的记忆」是漂移的现场：记忆每轮重拼，拼进去的就参与竞价；「计划 = 被跟踪的状态」与本题的状态外置层是同一件事。
- **同一条判据**：[[Q11-MCP与Skill|Q11]] —— 「经不经过模型」在本题分软硬三层，在 Q11 解释沙箱为什么必须在内核；hook 与沙箱是同一档。
- **无事件的失败**：[[Q09-主子Agent通信与异常|Q09]] —— 跑偏只能靠验证器；漂移同样不崩不卡、正常返回，只能靠执行前检查。「模型只能读到被写进上下文的字」贯穿两题。
- **接口的另一半**：[[Q05-StructuredOutput|Q05]] —— schema 管形状不管内容；「必填强迫幻觉」是约束解码的反面。

## 9. 核心结论

> **漂移的本质不是「忘了」，是「被压过去了」——上下文里一切都是 token，一起参与注意力竞价，早期约束的票数必然被稀释。所以治理必须分层：外置记忆解决「还在不在」；只有把约束搬出上下文、变成执行前不经过模型的确定性检查，才解决「在但没照做」。工具幻觉是同一件事的另一面：schema 管形状不管内容，越严越逼编造；内容层靠校验器挡离谱、留空防硬填、干净重试防编造、多次采样测确定性——四招没有一招指望模型自觉。判断任何一招是软是硬，只问一句：它经不经过模型。**
