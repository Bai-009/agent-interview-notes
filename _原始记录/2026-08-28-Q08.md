## 出题人反馈（第二轮：三柱收束）

> 你那个"疑问"不是疑问，是正确答案。 而且你自己给出了机制——"贪心"、"短视"这两个词就是它。
>
> 先确认第一问： `tool_result` 塞回 context，对。这就是那个关键性质——知识不是被"注入模型"的，是被拼进下一轮的输入里的。 模型每一轮都是失忆的，你每次都在重新拼一份"你之前经历了这些"给它看。
>
> 现在说规划，这是这题真正的深水区，而你已经站在正确的一侧了。
>
> 默认的循环里，模型没有任何机制能持有一个跨轮的计划。每一轮它做的事只有一件：看当前这一坨上下文，输出下一个动作。 就一步。
>
> 所以严格说，那个循环里不存在"计划"这个东西。存在的只是一连串各自独立的、贪心的下一步。
>
> 看起来像有计划，是因为上下文里留着前几轮的痕迹——它读到"我刚才搜了 A、读了 B"，于是接出一个像是"第三步"的东西。计划的连续性不在模型里，在上下文的文本里。
>
> 而你那句"除非把 plan 的内容放在最前面，让模型每次都能看到"——这就是 plan mode 的全部实现。
>
> 不是模型学会了规划。是：先让它生成一份计划文本 → 这份文本被固定在上下文里 → 之后每一轮它都重新读到这份计划。
>
> 计划是一个被反复重读的文档，不是一个被持有的意图。
>
> 这个区分有个非常实际的后果，也是你那个"短视"直觉的代价所在：
>
> 模型可以偏离自己写的计划，而且不会有任何东西报警。因为它不是在"执行计划"，它只是在"读到一段包含计划的文本，然后贪心地接下一步"。计划对它是建议性的上下文，不是约束性的状态。
>
> 所以真正管用的做法，是把计划从"一段文本"变成"一个被跟踪的状态"——写进文件，每步勾掉一项，每轮把当前状态重新读进来。 这时候"到哪一步了"就不再依赖模型记得，而是有个外部的东西在记账。
>
> （你现在用的 Claude Code 里那个 todo 清单，就是这个。它看起来像 UI 装饰，其实是把计划从易失的对话里搬到了一个可被机械跟踪的地方。）
>
> 所以三根柱子拼齐了，全是你自己的话：
>
> * 工具：模型只有请求权（tool_use），执行权在外面的代码，`end_turn` 也不是通行证。
> * 知识：靠 tool_result 拼进下一轮输入——不是注入模型，是重拼上下文。
> * 规划：默认没有规划，只有贪心的下一步；所谓的"计划"是一份被固定在上下文里反复重读的文本。
>
> 杀手句：
> Agent 的自主性不来自模型能规划，而来自"贪心的一步"被放进了一个会把结果拼回去的循环里。计划、记忆、进度，全都不在模型内部——它们是每一轮被重新递给它的文本。
