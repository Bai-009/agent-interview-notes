## Q01 出题

> 第一题，你先答，60 秒版本：
>
> Prompt Engineering 的核心目标是什么？为什么模型对同一件事，换个说法效果会差十倍？
>
> 提示只有一句：别背"写清楚需求"这种话——用我们挖过的那三层原理里的第一层来答。答完我给你看题库的标准答案，然后我们把它打穿。

### 我的裸答

> 核心目标是改变模型的输出分布，让正确的答案的概率分布更尖锐，让你想要的的next-token能够以更高的概率去输出。

### 反馈

> 这个答案已经在及格线上面了。先给你看题库的标准答案，你对照一下：
>
> 题库版：大模型本质是概率生成器，你给什么输入，它就按概率分布去接。Prompt 写得模糊，概率就分散到八百个方向上；写得精准，概率就集中到你想要的那条路上。所以核心不是"哄模型"，是把你的意图翻译成模型最容易理解的形式。
>
> 你的答案和它同构，而且你用了更准的词——"分布尖锐"比"集中到一条路"更接近机制。这题你过了。
>
> 但我们的规矩是打穿它。现在加生产级那一层，两刀：
>
> **第一刀：说清楚"为什么会差十倍"——题库其实没答这半题。**
>
> 题库只说了"模糊则分散，精准则集中"，但没解释为什么换个说法差距能有十倍这么大。真正的机制是：
>
> 模型没有"理解你的意图"这个独立步骤。它做的事只有一件——把你的输入当成一篇文章的开头，续写最像的下文。所以你的 prompt 真正干的活，不是"传达需求"，是选择模型进入哪个分布区。
>
> "帮我写个请假邮件"——这个开头在训练语料里，后面跟着的是什么？各种随意的、口语的、长短不一的东西。你落进了一个宽而杂的分布区。
>
> "你是职场邮件助手，写一封事假邮件，语气正式，200 字以内"——这个开头激活的是完全另一片语料：规范的、格式化的、职场文书样本聚集的区域。
>
> 十倍的差距不是模型"更努力了"，是你把它扔进了另一个街区。 同一个模型，两个 prompt，等效于两个不同的条件分布——差的不是执行质量，是起点就不在同一片语料里。
>
> 杀手句版本：Prompt 不是指令，是坐标。它决定的不是模型"做什么"，是模型"从哪片分布里开始采样"。
>
> **第二刀：这道题在 2026 年有一个追问，题库没覆盖，但字节这个岗位大概率会追——**
>
> "既然 prompt 这么重要，为什么业界都在说 prompt engineering 已死、context engineering 才是重点？"
>
> 这个追问你其实有独家弹药——你自己那条思想线的第一天就是它：prompt 会被生成。凡是符号都可以被模型生成，所以"把 prompt 写好"这个技能本身正在被吸收掉。但没被吸收的是外面那圈：每一轮往窗口里放什么、不放什么、工具返回怎么设计、记忆怎么外置——这些是结构决策，不是措辞决策。
>
> 杀手句版本：单条消息的措辞在贬值（因为可生成），窗口内容的取舍在升值（因为那是架构判断）。Prompt engineering 没死，它长大了改名叫 context engineering。

## Q02 出题

> 这题收了。第二题，连着考，因为它就是刚才那个追问的正面版：
>
> System Prompt / Few-shot / CoT 在 Prompt 设计中各起什么作用？
>
> 你先答。提示：题库的答案是"三个策略解决三个问题"——你可以背出类似的，但我要你试着更进一步：用"分布"这一个词，把三者统一起来说。三个东西各自在对分布做什么不同的动作？

### 我的裸答

> system prompt就像该任务的背景音乐，在残差链接的关系和专门后训练的基础下，最前面的提示词会被模型认为是更重要的系统指令。遵循的效果更好，而且由于attention的机制，后续的所有token都会看到前面的系统提示词的内容，也就是始终影响着后续的token的预测和生成。
> few-shot其实就是举例子，模型看不到的对模型而言就是没有，你给到一些例子，本身就是在让模型学习，从而改变了输出的分布，让他更该知道当下的这个问题该如何处理。
> COT，现在的模型都是thinking模型，thinking就可以看作是工业版本的COT，举个例子就很好的说明COT，算9999*9999假如这里面是5个token，假设模型是100层layer层，那么这五个token就走过来500层layer层。模型并不能真实的去额外的思考里面的关系，从而自信的给出一个差不多的答案。如果我给的提示词是先算10000*10000，再减去20000再减去1，用了大概20个token，走过了2000层layer层，并且还降低了单词回答问题的难度，就好像一个是在口算答案，一个是有一张草稿纸把过程写了下来。因为模型的layer层是固定的，所以COT的本质就是在用额外的token换layer层，换模型的聪明。

### 反馈

> Thought for 54s
>
> 这题你不只过线——CoT 那一段已经把题库打穿了。但有一处要修，我先把验收做完整。
>
> 及格线对照。 题库版：System Prompt 解决"始终按某角色回答"，全程生效；Few-shot 解决"格式对齐"，给例子比写规则管用；CoT 解决"复杂推理易错"，把过程写出来能纠偏。——三句功能描述，全对，全浅。你的答案在两处明显高于它：system prompt 你给了机制（后训练的角色优先级 + 因果注意力让后续每个 token 都看得到它），CoT 你给了真正的第一性解释。
>
> 先修那一处：「残差链接」放错地方了。 残差是层与层之间的信息通路，管的是"深度方向上信息不丢"，跟"前面的 token 更重要"没有关系。你想抓的那个现象是真实存在的，它叫 attention sink：注意力会不成比例地锚定在序列最前面的几个 token 上——所以开头位置确实自带加成。加上你说对的那条"专门后训练过角色层级"，就齐了。
>
> 而"角色层级是训练出来的"这一条，藏着一个生产级的推论，值得你现在就焊上：system > user > 工具返回，这个优先级不是架构强制的，是学出来的偏好。 架构层面，所有 token 走的是同一条通道、同一套注意力——这就是提示注入在结构上无法根治的原因：指令和数据物理上是同一种东西，"谁该听谁的"只是一个被训练加强过的倾向，而倾向可以被足够刁钻的输入压过去。你前几天问过的"模型分不清指令和数据"，根子就在这。
>
> CoT 那段，你答出了机制的一半，我把另一半补上。
>
> 你说的"token 换 layer"完全正确：模型每生成一个 token 只走一次固定深度的前向,难题硬要一步出答案，就是逼一个 100 层的电路瞬间完成需要 2000 层的计算。多生成 token = 购买串行计算步数。这个解释大多数面试者给不出来。
>
> 但你自己那个"草稿纸"比喻里，还藏着第二个机制，比换深度更关键：写下来的中间结果，会变成后续 token 的输入。 没有 CoT 时，所有中间量只能挤在残差流那点宽度里暗算；写出来之后，"10000×10000=100000000"这个中间结果被序列化到了上下文里，后面每一步都能回头读它。草稿纸的价值不只是"多算了几步"，是草稿可以被重新读取——它是外置的工作记忆。你听这个说法耳熟吗？这就是"状态外置"的最小版本。 Agent 把任务状态写进文件，和模型把中间结果写进上下文，是同一个动作在两个尺度上。
>
> 再补两条生产级注脚：其一，thinking 模型 = 被 RLVR 训练过的 CoT——原生 CoT 是"提示出来的习惯"，thinking 是"被可验证奖励强化过的能力"，链条质量完全不同，而且现在是可调的成本旋钮（思考深度档位，你在 Codex 里用 Alt 键调的就是它）。其二，一条诚实的边界：写出来的链不保证是真实的计算过程——有研究证明模型可能先"算"出答案再补一条看起来合理的推导。所以草稿纸提升性能是实的，但把草稿当成"它真实的思路"去审计，不保真。
>
> Few-shot 给你一条 2026 年的反直觉更新：对强推理模型，few-shot 有时降分——例子会把模型锚死在模仿模式上，抑制它自己的推理。所以现在的实务是：格式约束用 schema，推理任务倾向 zero-shot，few-shot 留给"格式怪异且说不清"的场景。例子还有个隐性成本：它们永久占窗口。
>
> 最后，你欠的那个统一没交齐——我替你合上，这就是杀手句：
>
> 三者是对同一个条件分布动的三种手术：System prompt 定分布的底色（全程条件化），few-shot 钉分布的形状（用样本示范代替规则描述），CoT 把一次尖不起来的采样，拆成一串尖得起来的采样。
>
> 最后那半句你品一下——它就是你自己的话:"降低了单次回答的难度"。每个中间步骤的分布都是尖的,所以整条链的可靠性远高于一步到位的那次平坦采样。
