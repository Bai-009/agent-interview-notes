## 出题方法：设计为主，面经对表（2026-11-22 起）

> 用户 2026-11-22：「没有真实的面试题，你是否能通过对前沿业务的理解和需求，还有技术本身的架构和原理，自己去设计一套呢？」
> 起因：personal agent 火了大半年，面经里还找不到原帖。**面经落后于前沿**，只跟着面经出题，题库永远慢一拍。

**三步**

1. **业务要什么**：用户为什么付钱、平台为什么放行，每条线列一份需求清单。
2. **技术卡在哪**：四条根原理加推论，再加这条线自己的约束。
3. **两者撞上的地方出题**：一道题 = 一个需求撞上一条约束，而且有人必须当场做决定。

**四条根原理**（与复习原始记录里 2026-10 的根原理草案一致；写进[知识网络](../00-索引/知识网络.md)之前，仍等用户确认）

- **根1** 模型只是在按分布抽下一个 token：它说的每一句话，包括「我做完了」，都是抽出来的。
- **根2** 一次调用只由权重和输入决定，调用之间什么都不留：记忆、计划、进度都得写成文字，每轮重新喂进去。
- **根3** 上下文是预算：注意力此消彼长，每个 token 都要算力、要钱。
- **根4** 压缩必有损失：嵌入、切块、摘要、子 Agent 的汇报、训进权重，都是。补救是留一个指回原文的指针。
- **推论** 经过模型的都是概率；必须成立的事，交给模型之外的东西（代码、权限、操作系统）。

**每道题过五条检查**

1. 有一个真实的决定挂在上面：答案不同，团队做的事就不同。
2. 能追到至少一条根原理或约束。
3. 背不出来：换一个场景，答案就要重新推。
4. 一半能接在已经推出来的结论上（锚点写进题眼）。
5. 不泄题：碰到未答的题，题眼留空，必要时连题面一起折叠。

**五种问法**：设计（你来做一个）、排障（出了事先查什么）、取舍（A 还是 B，什么时候）、估算（要多少钱、多少卡、多久）、反事实（模型能力翻十倍、价格降到十分之一，什么该删）。

**面经改当校准，不当题源**：每轮捞到的真题，拿来映射到设计出的题上。映射得上，说明这道题问在点子上；映射不上，说明需求或约束列漏了，回去补清单再出题。2026-11-03 复习时考的两道新题（退款 Agent、跑了四十轮的编程 Agent），就是这样设计的，都不来自面经。

> **进度**：四条线都已按这个方法过了一遍（v1.1 做 P 线，v2 做 T、M、I）。**对表结果**：T、M、I 原有的 33 道题，全部对得上某个「需求 × 约束」，说明这张表没有偏；对不上的空格补成了新题。最缺的是**估算题**和**反事实题**：v1 只有一道估算题（I09，面经原文），反事实只在 T01 的题眼里带了一句。

## 题单

### Agent 工程（T）

**这条线的需求**（企业为什么愿意上 Agent、为它付钱）

- **需1 办成且验得了**：复杂、多步的事能做完，做完了能验收
- **需2 可控**：不越权，不做收不回的错事；人能随时插话、叫停
- **需3 查得清**：出了事，能追到哪一步、为什么
- **需4 算得准**：成本、时延、成功率稳定，能报价、能承诺
- **需5 接得上**：接得上现有系统、别家的工具和 Agent
- **需6 撑得住规模**：工具、技能、子 Agent 越来越多，效果不往下掉
- **需7 改得放心**：改了 prompt、换了模型，知道是变好还是变坏
- **需8 跑得久**：跨会话、跨天，进程挂了能接着干

**这条线的约束**：根1–根4 与推论（见「出题方法」），再加六条——

- **约1 动作有后果**：调用会改变外部世界，有的改了收不回
- **约2 外部世界不归你管**：别人的接口、限流、故障、条款
- **约3 不止一方在动**：多个 Agent、多个用户、多个进程同时在改东西
- **约4 时间在走**：任务一跑几小时到几天，进程会死，环境会变
- **约5 读到的东西不全可信**：工具返回值、网页、文件里可能夹着指令
- **约6 模型在换代**：每隔几个月，就有更强、更便宜的模型

### Personal Agent（P）

> **v1.1 起按设计法出题**（见「出题方法」）。这条线没有面经原帖，题面全部是维护方设计；[调研 2026-11](题库调研-2026-11.md) 第 3.1 节的产品动态，只用来证明下面的需求真实存在，不当题源。

**这条线的需求**（用户为什么付钱、平台为什么放行）

- **需1 办成**：把事做完，不是给建议
- **需2 不用盯**：自己在后台跑，到点自己动
- **需3 懂我**：记得这个人的偏好和历史
- **需4 别闯祸**：花钱、发出去的话，不能错
- **需5 守秘密**：数据不外泄，说忘就忘
- **需6 算得过账**：订阅费要盖得住调用成本
- **需7 处处能用**：进得了各家 App 和平台
- **需8 说得清**：出了事，查得清它做了什么、为什么做
- **需9 测得出**：知道它这周比上周办得好还是差

**这条线的约束**：根1–根4 与推论（见「出题方法」），再加四条——

- **约1 它的手在哪**：在哪台机器上、用谁的权限动手
- **约2 对面是别人家的系统**：接口、界面、条款、身份，都由对方定
- **约3 时间在走**：一跑几个月，世界会变，进程会死
- **约4 它读到的东西不全可信**：邮件、网页、消息里可能夹着指令

### 模型架构与算法（M）

**这条线的需求**（市场要模型变成什么样）

- **需1 更便宜**：每个 token 的成本往下走
- **需2 更快**：首字快，吐字快
- **需3 更长**：读得下、也用得好很长的上下文
- **需4 更会做事**：推理、调工具、多轮把事做完
- **需5 更稳**：少编造，听指令，格式对（一期 Q04、Q05 已覆盖，本线不另出）
- **需6 能看**：读图、读屏幕
- **需7 能改**：能被后训练成你要的样子

**这条线的约束**：根1–根4 与推论，再加六条模型自己的约束。这六条本身就是 M01–M05 和 Q13 的一半答案，**折叠**：

<details>
<summary>⚠️ M 线约束清单（维护方出题用；M01–M05 与 Q13 作答前不建议展开）</summary>

- **约1** 注意力让每个 token 都去看它前面的全部 token：长度一涨，计算和缓存一起涨
- **约2** 每生成一个 token，激活的参数都要过一遍：参数越多，每个 token 越贵
- **约3** 权重和 KV cache 都得放进显存：放不下，就跑不了
- **约4** 位置靠编码告诉模型：训练没见过的距离，只能靠外推
- **约5** 训练信号：预训练只问「下一个 token 对不对」，后训练才加上奖励
- **约6** 奖励会被钻空子：模型优化的是你写下的奖励，不一定是你想要的东西

<summary>⚠️ I 线：需求、约束与 I01–I14（Q14 作答前不建议展开）</summary>

**这条线的需求**（服务方和买方各要什么）

- **需1 每个 token 更便宜**
- **需2 回得快**：首字快，吐字稳
- **需3 扛得住高峰**
- **需4 同一批卡服务更多人**
- **需5 撑得住长上下文和多轮 Agent**
- **需6 训得出来、训得快**
- **需7 价格表上有利润**

**这条线的约束**

- **约1 算力有上限**：每秒能做的乘加次数是定的
- **约2 显存容量有上限**：权重和 KV cache 要一起装下
- **约3 显存带宽有上限**：每吐一个 token，都要把权重和缓存从显存里读一遍
- **约4 卡之间说话慢**：机内快，机间慢
- **约5 排队**：吞吐和时延此消彼长
- **约6 生成是串行的**：下一个 token 要等上一个
